* completion/
:PROPERTIES:
:CUSTOM_ID: completion-modules
:END:

completion 層は、候補を絞り込み、選ぶための仕組みの層です。 =early-init → core → ui → auth → completion → orgx → vcs → dev → utils → personal= の
並びで、auth の次、orgx の前にあります。ここより下（early-init、core、ui、auth）に依存できますが、
orgx 以降には依存できません。

補完は、2 つの場面に分かれます。

- *ミニバッファの補完* — =M-x= やファイル選択など、ミニバッファで候補を選ぶ場面です。Vertico が縦に候補を並べ、
  Marginalia が注釈を添え、Consult が検索とナビゲーションを、Embark が候補への操作を足します。
- *バッファ内の補完* — 入力中のシンボルを補う場面です。Corfu がポップアップで候補を出し、Cape が候補の出どころ
  （ CAPF ）を増やします。Emacs 31 のインライン表示（ completion-preview ）も使います。

どちらの場面でも、絞り込みは同じ Orderless（空白で区切った語を、順序を問わずに当てる）が担います。

*構成*

| モジュール | 責務 |
|------------|------|
| =completion-core= | 補完スタイル（orderless + basic）と、Emacs 31 の補完エンジンの設定 |
| =completion-vertico= | Vertico、Marginalia、vertico-posframe、ファイル名補完の操作 |
| =completion-consult= | Consult と consult-dir。xref の候補表示 |
| =completion-embark= | Embark と wgrep。候補に対する文脈依存の操作 |
| =completion-corfu= | Corfu、Cape、kind-icon、corfu-terminal、Emacs 31 の completion-preview |
| =completion-icons= | ibuffer と補完の注釈への nerd-icons の統合 |
| =completion-capf= | モード別の CAPF の並びと、補完のカテゴリ別スタイル |
| =completion-org-src= | Org のソースブロックの編集バッファ向けの補完設定 |
| =completion-lsp= | プロジェクトを切り替えたときの、不要になった Eglot サーバの停止 |

ロード順は、上の表の順です（ =lisp/modules.el= の =my:modules= ）。

*この層の方針*

- *初期化は一度だけ、フレームができてから* — Vertico、Marginalia、Corfu、kind-icon、Cape は、 =window-setup-hook= で
  1 回だけ初期化します（ =core-runtime-add-hook-once= が、初回で自分をフックから外します）。フレームを作るたびに
  設定が走らないようにするためです。
- *デーモンでは、実フレームを待つ* — posframe のように画面の種類に依存するものは、ロード時に =display-graphic-p= で
  分けません。デーモンの起動時には実フレームがなく、判定が常に偽になって、あとから =emacsclient -c= で
  フレームが繋がっても、再試行されなくなるためです。初回のグラフィカルなフレームができた時点で、一度だけ有効にします。
- *正となる設定は 1 か所に置く* — 補完のカテゴリ別の上書き（ =completion-category-overrides= ）は、
  =completion-capf= だけが持ちます。複数のファイルで定義すると、あとから読まれたほうが黙って勝つためです。


* completion/completion-core.el
:PROPERTIES:
:CUSTOM_ID: completion-core
:header-args:emacs-lisp: :tangle ../lisp/completion/completion-core.el
:END:

補完の土台になる設定です。ほかのモジュールは、ここで決めた補完スタイルの上に載ります。

- *補完スタイル* — =completion-styles= は =orderless= と =basic= です。 =orderless= は、空白で区切った複数の語を、
  順序を問わず、どこにでも一致させます。 =basic= は、 =orderless= で当たらなかったときのフォールバックです。
- *Emacs 31 の補完エンジン* — Emacs 31 以上でだけ有効です（ =:if (>= emacs-major-version 31)= ）。
  - =completion-eager-display= と =completion-eager-update= は =nil= に固定します。どちらも =*Completions*= を
    ポップアップして逐次更新する機能で、その役割は Vertico がすでに担っています。将来 Emacs の既定値が変わっても、
    候補のリストが二重に出ないようにするためです。
  - =completion-pcm-leading-wildcard= は =t= です。 =partial-completion= が、どこでも一致する（部分一致の）ように
    振る舞います。 =orderless= の隣に置くフォールバックとして、望ましい挙動だからです。
- *カテゴリ別の上書きは、ここでは設定しない* — 正となる表は =completion-capf= にあります。両方に書くと、
  あとから読まれる =completion-capf= が黙って勝ち、ここでの宣言が誤解を招くものになります。

#+begin_src emacs-lisp
  ;;; completion/completion-core.el --- 補完のコア設定 -*- lexical-binding: t; -*-
  ;;
  ;; Copyright (c) 2021-2026
  ;; Author: YAMASHITA, Takao
  ;; License: GNU GPL v3 or later
  ;;
  ;; Category: completion
  ;;
  ;;; Commentary:
  ;;
  ;; 補完のコア: orderless 補完スタイル。
  ;;
  ;; 本ファイルの責務:
  ;; - orderless を導入し、`completion-styles' を orderless + basic に設定する
  ;;
  ;; 注意: `completion-category-overrides' はここでは設定しない。正式かつ拡張された
  ;; 上書きテーブル（file、symbol、keyword、tex、dabbrev）は completion-capf.el にあり、
  ;; 本モジュールより後にロードされる。両方のファイルで上書きを定義すると、
  ;; 「後勝ち」の意味論により completion-capf.el が静かに勝ってしまい、ここでの宣言は
  ;; 誤解を招くものになる。正となる情報源を 1 つに絞る方が明快で、推論も容易である。
  ;;
  ;;; Code:

  (eval-when-compile (require 'leaf))

  (leaf orderless
    :straight t
    :custom
    ((completion-styles . '(orderless basic))))

  ;; ---------------------------------------------------------------------------
  ;; Emacs 31 の補完エンジン
  ;; ---------------------------------------------------------------------------
  ;; - `completion-eager-display' / `completion-eager-update' は "*Completions*"
  ;;   バッファをポップアップし、逐次更新する。その役割は既に Vertico が担っているため、
  ;;   将来 Emacs の既定値が変わっても候補リストが二重に現れないよう、両者を nil に固定する。
  ;;
  ;; - `completion-pcm-leading-wildcard' により partial-completion スタイルが substring
  ;;   （どこでも一致）のように振る舞う。orderless の隣に置くフォールバックの `basic'
  ;;   補完としては、これが望ましい挙動である。
  ;; - `flex' スタイルは Emacs 31 で再実装された（高速化とランキング改善）。
  ;;   orderless のディスパッチャに頼るより、file カテゴリで直接使う価値がある。
  ;;
  (leaf emacs
    :straight nil
    :if (>= emacs-major-version 31)
    :custom
    ((completion-eager-display        . nil)
     (completion-eager-update         . nil)
     (completion-pcm-leading-wildcard . t)))

  (provide 'completion-core)
  ;;; completion/completion-core.el ends here
#+end_src

* completion/completion-vertico.el
:PROPERTIES:
:CUSTOM_ID: completion-vertico
:header-args:emacs-lisp: :tangle ../lisp/completion/completion-vertico.el
:END:

ミニバッファの UI です。候補を縦に並べ、グラフィカルな画面では、画面の中央に子フレーム（posframe）で表示します。

*初期化のしかた*

- *Vertico と Marginalia* — =vertico-mode= と =marginalia-mode= は、フレームに依存しません（ディスプレイがなくても、
  ミニバッファの補完は動きます）。 =window-setup-hook= で 1 回だけ有効にします。
- *vertico-posframe* — 画面の種類に依存するので、上とは別に扱います。
  - 非デーモン: =window-setup-hook= の時点でグラフィカルなら、一度だけ有効にします。
  - デーモン: 初回のグラフィカルなフレームができた時点で、 =core-runtime-run-on-first-graphic-frame= が、一度だけ
    有効にします。子フレームの背景色が、フレームの実体化の途中ではまだ確定しないことがあるため、1 tick 遅らせています。
  - =leaf= の =:if= は、モジュールのロード時に一度だけ評価されます。デーモンの起動時は実フレームがなく、
    常に偽になって、パッケージ自体が一度もロードされないバグがありました。そこで =:if= をやめ、 =:require nil= にして、
    実際の =require= と有効化は =completion-vertico--activate-posframe= に任せています。

*設定*

- 候補の表示数は 15 です（ =vertico-count= ）。posframe の枠の幅は 2 です（ =vertico-posframe-border-width= ）。
- =marginalia-align= は =right= です。注釈を右端に寄せます。この値は、 =marginalia= を導入する =leaf= が持ちます。
  =completion-icons= には置きません。
- ファイル名補完は =vertico-directory= で操作します。

| キー | 動作 |
|------|------|
| =RET= | ディレクトリの上では、そのディレクトリへ入る |
| =DEL= | ディレクトリの区切りの直後なら、パスを 1 階層戻る |
| =M-DEL= | 単語（パスの 1 階層）ごと戻る |

  =~/= や =/= を打ち直したときは、入力済みのパスを =vertico-directory-tidy= が捨てます。

#+NAME: completion-vertico
#+begin_src emacs-lisp
  ;;; completion/completion-vertico.el --- Vertico によるミニバッファ UI -*- lexical-binding: t; -*-
  ;;
  ;; Copyright (c) 2021-2026
  ;; Author: YAMASHITA, Takao
  ;; License: GNU GPL v3 or later
  ;;
  ;; Category: completion
  ;;
  ;;; Commentary:
  ;;
  ;; posframe 表示と marginalia 注釈を備えた Vertico のミニバッファ UI。
  ;;
  ;; 本ファイルの責務:
  ;; - 二重初期化を避けるため、`window-setup-hook' で vertico、marginalia を
  ;;   ちょうど一度だけ初期化する
  ;; - posframe 表示はグラフィカルセッションでのみ、初回のグラフィカル
  ;;   フレームができた時点で一度だけ有効化する（daemon 対応。vertico/
  ;;   marginalia の初期化とは独立に扱う）
  ;; - vertico の候補表示数と posframe の枠幅を設定する
  ;; - ファイル名補完を `vertico-directory' でディレクトリ単位に操作できるようにする
  ;;; Code:

  (eval-when-compile (require 'leaf))

  (declare-function core-runtime-add-hook-once "core-runtime")

  (defun completion-vertico--init ()
    "Initialize Vertico and Marginalia.
  These are frame-independent (minibuffer completion works without a
  display), so unlike posframe below, no daemon branch is needed here.
  一度だけ実行する保証は `core-runtime-add-hook-once' が担う（下の登録を参照）。"
    (vertico-mode 1)
    (marginalia-mode 1))

  ;; 初回実行で自身を window-setup-hook から外す。
  (core-runtime-add-hook-once 'window-setup-hook #'completion-vertico--init)

  ;; vertico-posframe だけは vertico-mode / marginalia-mode と切り離して
  ;; 扱う。--daemon 起動時、上の completion-vertico--init は実フレームの無い
  ;; window-setup-hook で走ってしまうため、その中で単純に (display-graphic-p)
  ;; を見るだけだと daemon では常に nil と判定され、しかも
  ;; completion-vertico--init が自分自身をフックから除去して
  ;; しまうため、後から emacsclient -c で本物のフレームが繋がっても
  ;; 二度と再試行されない（posframe が永久に効かないバグ）。
  ;;
  ;; ligature / nano-modeline と同じパターンで、初回のグラフィカルフレームが
  ;; できるまで独立して遅延させる。
  (defun completion-vertico--activate-posframe (&optional _frame)
    "posframe / vertico-posframe を require し、有効化する。"
    (require 'posframe)
    (require 'vertico-posframe)
    (setopt vertico-posframe-border-width 2)
    (vertico-posframe-mode 1)
    (require 'vertico-multiform nil t))

  ;; nano-modeline / ui-theme と同じ理由（after-make-frame-functions はフレーム
  ;; 実体化の途中で走り、色がまだ確定していない）で、posframe の子フレーム背景色
  ;; も同種の影響を受け得る。直接の破損は未確認だが、同じ
  ;; `core-runtime-run-on-first-graphic-frame' で予防的に 1 tick 遅らせておく。
  (defun completion-vertico--maybe-activate-posframe ()
    "グラフィカルな画面なら vertico-posframe を有効化する。非 daemon 用。"
    (when (display-graphic-p)
      (completion-vertico--activate-posframe)))

  (declare-function core-runtime-run-on-first-graphic-frame "core-runtime")

  (if (daemonp)
      (core-runtime-run-on-first-graphic-frame #'completion-vertico--activate-posframe)
    (core-runtime-add-hook-once 'window-setup-hook
                                #'completion-vertico--maybe-activate-posframe))

  (leaf vertico
    :straight t
    :custom ((vertico-count . 15)))

  ;; vertico 同梱の拡張。ファイル名補完で RET がディレクトリへ入り、DEL / M-DEL が
  ;; パスを 1 階層ずつ戻る。`vertico-directory-tidy' は、~/ や / を打ち直したときに
  ;; 入力済みのパスを捨てる。
  (leaf vertico-directory
    :straight nil
    :after vertico
    :bind (:vertico-map
           :package vertico
           ("RET"   . vertico-directory-enter)
           ("DEL"   . vertico-directory-delete-char)
           ("M-DEL" . vertico-directory-delete-word))
    :hook (rfn-eshadow-update-overlay-hook . vertico-directory-tidy))

  (leaf marginalia
    :straight t
    ;; marginalia-align は defcustom である。どの leaf 宣言にも属させず浮かせるのではなく、
    ;; marginalia の leaf ブロックが所有する形にしている。
    :custom ((marginalia-align . 'right)))

  (leaf posframe
    :straight t
    :require nil)

  ;; leaf の :if は「モジュールのロード時」に一度だけ評価される。--daemon
  ;; 起動時はその時点で実フレームが無いため (display-graphic-p) は常に nil
  ;; となり、vertico-posframe パッケージ自体が永久にロードされなかった
  ;; （ligature が :when で抱えていたのと同じ daemon 対応バグ）。
  ;; :if を撤去して :require nil にし、実際の require と有効化は上の
  ;; completion-vertico--activate-posframe に委ねる。
  (leaf vertico-posframe
    :straight t
    :after (vertico posframe)
    :require nil)

  (provide 'completion-vertico)
  ;;; completion/completion-vertico.el ends here
#+end_src

* completion/completion-consult.el
:PROPERTIES:
:CUSTOM_ID: completion-consult
:header-args:emacs-lisp: :tangle ../lisp/completion/completion-consult.el
:END:

検索と、定義への移動を、候補つきで行うための Consult の設定です。割り当てのほとんどは =ui-keys.el= の
leader にあり、ここでは Consult 自身の挙動と、 =consult-dir= のキーを決めます。

- *xref の候補表示* — =xref-show-xrefs-function= と =xref-show-definitions-function= を =consult-xref= にします。
  定義や参照が複数あるとき、候補をプレビューつきで選べます。
- *プレビューの遅延* — =consult-preview-key= は =(:debounce 0.4 any)= です。候補を動かすたびにプレビューが走ると
  重いので、0.4 秒止まってから表示します。
- *絞り込みのキー* — =consult-narrow-key= は =<= です。Consult のコマンドの中で =<= を押してから、
  種類のキーを押すと、候補を種類で絞り込めます。
- *レジスタのプレビュー* — =register-preview-delay= は 0.5 秒で、整形に =consult-register-format= を使います。
- *consult-dir* — =C-x C-d= で、プロジェクトやブックマークのディレクトリへ移れます（組み込みの =list-directory= を
  置き換えます）。ミニバッファの中では、 =C-x C-d= でディレクトリの一覧、 =C-x C-j= でそこからのファイル選択です。

#+begin_src emacs-lisp
  ;;; completion/completion-consult.el --- Consult による検索とナビゲーション -*- lexical-binding: t; -*-
  ;;
  ;; Copyright (c) 2021-2026
  ;; Author: YAMASHITA, Takao
  ;; License: GNU GPL v3 or later
  ;;
  ;; Category: completion
  ;;
  ;;; Commentary:
  ;;
  ;; Consult: 検索と相互参照ナビゲーションの強化。
  ;;
  ;; 本ファイルの責務:
  ;; - より豊かな候補表示のため、`xref-show-xrefs-function' と
  ;;   `xref-show-definitions-function' を `consult-xref' 経由にする
  ;; - プレビューの遅延、絞り込みキー、レジスタのプレビューを設定する
  ;; - consult-dir で、補完中にプロジェクトやブックマークのディレクトリへ移れるようにする
  ;;; Code:

  (eval-when-compile (require 'leaf))

  (declare-function consult-xref "consult-xref")
  (declare-function consult-register-format "consult")

  (leaf consult
    :straight t
    :custom ((xref-show-xrefs-function        . #'consult-xref)
             (xref-show-definitions-function . #'consult-xref)
             ;; 候補を移動するたびにプレビューが走らないよう、0.4 秒待つ。
             (consult-preview-key            . '(:debounce 0.4 any))
             (consult-narrow-key             . "<")
             (register-preview-delay         . 0.5)
             (register-preview-function      . #'consult-register-format)))

  ;; C-x C-d は組み込みの `list-directory' を置き換える。ミニバッファ内では
  ;; C-x C-d でディレクトリ一覧、C-x C-j でそこからファイルを選べる。
  (leaf consult-dir
    :straight t
    :bind (("C-x C-d" . consult-dir)
           (:vertico-map
            :package vertico
            ("C-x C-d" . consult-dir)
            ("C-x C-j" . consult-dir-jump-file))))

  (provide 'completion-consult)
  ;;; completion/completion-consult.el ends here
#+end_src

* completion/completion-embark.el
:PROPERTIES:
:CUSTOM_ID: completion-embark
:header-args:emacs-lisp: :tangle ../lisp/completion/completion-embark.el
:END:

候補（やバッファの中の対象）に対して、文脈に合った操作を選んで実行するための Embark の設定です。
Consult と組み合わせて、検索結果の一括編集まで繋ぎます。

*キー*

| キー | コマンド | 用途 |
|------|----------|------|
| =s-/= | =embark-act= | 対象に対する操作を選ぶ |
| =s-;= | =embark-dwim= | 対象の既定の操作を実行する |
| =C-<f2>= | =embark-bindings= | 今のバッファのキーバインドを一覧する |

これらは Embark 固有のコマンドなので、汎用の =ui-keys.el= ではなく、ここで割り当てます。

*設計のポイント*

- =prefix-help-command= を =embark-prefix-help-command= にします。 =C-x= などの接頭辞のあとに =C-h= を押すと、
  そのキーマップのコマンドを、候補つきで選べます。
- =embark-consult= を読み込むと、 =embark-collect= のバッファで =consult-preview-at-point-mode= が有効になり、
  集めた候補のプレビューが、ポイントの位置で出ます。
- *検索結果の一括編集* — =wgrep= を導入しています。 =consult-ripgrep= などの結果を =embark-export= で =grep-mode= の
  バッファに書き出し、 =C-c C-p= で編集を始め、 =C-c C-c= ですべてのファイルへ反映します。

#+begin_src emacs-lisp
  ;;; completion/completion-embark.el --- Embark のアクション -*- lexical-binding: t; -*-
  ;;
  ;; Copyright (c) 2021-2026
  ;; Author: YAMASHITA, Takao
  ;; License: GNU GPL v3 or later
  ;;
  ;; Category: completion
  ;;
  ;;; Commentary:
  ;;
  ;; Consult と統合した Embark の文脈依存アクション。
  ;;
  ;; 本ファイルの責務:
  ;; - `prefix-help-command' を `embark-prefix-help-command' に設定する
  ;; - `embark-collect' バッファで `consult-preview-at-point-mode' を有効化する
  ;; - Embark 本体のグローバルキーバインドを設定する（s-/、s-;、C-<f2>）
  ;; - wgrep を導入する。consult-ripgrep などの結果を `embark-export' で grep-mode の
  ;;   バッファに書き出し、C-c C-p で編集、C-c C-c で全ファイルへ反映できる
  ;;; Code:

  (eval-when-compile (require 'leaf))

  (leaf embark
    :straight t

* completion/completion-corfu.el
:PROPERTIES:
:CUSTOM_ID: completion-corfu
:header-args:emacs-lisp: :tangle ../lisp/completion/completion-corfu.el
:END:

バッファの中で、入力中のシンボルの候補をポップアップで出す Corfu の設定です。候補の出どころ（ CAPF ）を Cape で増やし、
アイコンと、Emacs 31 のインライン表示を足します。

*初期化*

=window-setup-hook= で 1 回だけ、Corfu、popupinfo、history、kind-icon、Cape を有効にします
（ =completion-corfu--init= ）。このとき、 =completion-at-point-functions= の先頭に =cape-elisp-symbol= 、
=cape-file= 、 =cape-dabbrev= をこの順で足します。足し方は 1 回の =setq= と =append= で、優先順位（ elisp のシンボル、
ファイル、 dabbrev 、既存の並び）を明示します。

*設定*

- =corfu-auto= は =t= で、入力するとポップアップが自動で出ます。 =corfu-cycle= も =t= で、候補の端から反対側へ回ります。
- =tab-always-indent= は =complete= です。 =TAB= は、インデントできるときはインデントし、すでに整っているときは補完します。
- =corfu-popupinfo= は、選択中の候補のドキュメントを横に表示します。遅延は =(0.5 . 0.2)= です（最初の表示まで 0.5 秒、
  候補を替えたあとは 0.2 秒）。
- =corfu-history= は、選んだ候補を、次回から上位に出します。ただし履歴は =savehist-additional-variables= に載せません
  （ =core-history= が、Emacs 31 の履歴ファイルのマージを生かすため、ユーザー変数を足さない方針のため）。
  このため、候補の履歴は、そのセッションの中だけで効きます。
- =kind-icon= は、候補の種類（関数、変数など）のアイコンを、マージンに出します。

*端末（ emacs -nw ）*

Corfu のポップアップは子フレームなので、端末では使えません。端末のフレームの初期化（ =tty-setup-hook= ）のとき、
=corfu-terminal= で描きます。 =corfu-terminal-mode= は、フレームごとに切り替えられない大域のモードなので、
デーモンでは有効にしません（グラフィカルなフレームのポップアップを壊さないため）。

*Emacs 31 のインライン表示（ completion-preview ）*

ポップアップを開かずに、いちばん上の候補を、ポイントの先にゴーストテキストで出します。Emacs 31 以上でだけ有効です。

- =prog-mode= と =org-mode= で有効にします。3 文字以上のシンボルから出ます（ =completion-preview-minimum-symbol-length= ）。
- 並べ替えの関数を Corfu と共有します。プレビューの候補が、いつも Corfu が最初に挿入する候補と一致します。
  Corfu が並べ替えの関数を持たないときは、Emacs の既定のままにします。
- =vterm= 、 =eshell= 、 =comint= 、 =term= のバッファでは、プロセスの出力と衝突するので、出しません。
- 候補の切り替えは =M-n= と =M-p= です。

* completion/completion-capf.el
:PROPERTIES:
:CUSTOM_ID: completion-capf
:header-args:emacs-lisp: :tangle ../lisp/completion/completion-capf.el
:END:

モードごとに、バッファ内の補完の出どころ（ CAPF ）の並びを決めます。Cape の CAPF を、バッファローカルに組み立てます。

*モード別の CAPF の並び*

| モード | 並び | 関数 |
|--------|------|------|
| emacs-lisp、lisp-interaction | シンボル、ファイル、 dabbrev | =completion--elisp-capfs= |
| prog-mode | 既存の並びに、ファイル、 dabbrev を足す | =completion--prog-capfs= |
| text-mode | dabbrev、ファイル | =completion--text-capfs= |
| org-mode | dabbrev、ファイル、TeX の記号 | =completion--org-capfs= |
| sh、eshell | ファイル、 dabbrev | =completion--shell-capfs= |
| ielm、comint | 既存の並びに、 dabbrev を足す | =completion--repl-capfs= |

どの並びも =completion--set-capfs= が、 =completion-at-point-functions= にバッファローカルに設定します。重複は取り除き
（最初に出てきたものが勝つ）、フックが複数回走っても、結果が変わらないようにしています。

*カテゴリ別のスタイル*

=completion-category-overrides= は、このモジュールだけが持ちます（ =setopt= で設定）。 =completion-core= で決めた
orderless を、カテゴリごとに調整します。

| カテゴリ | スタイル |
|----------|----------|
| =file= | =basic= 、 =partial-completion= |
| =symbol= 、 =keyword= | =orderless= |
| =tex= 、 =dabbrev= | =basic= |

*Eglot との合流*

Eglot が管理するバッファでは、Eglot の候補（ =eglot-completion-at-point= ）に =cape-dabbrev= を合流させます
（ =completion--eglot-capfs= 。 =cape-capf-super= を使う）。 =eglot-managed-mode-hook= は、有効にするときと
無効にするときの両方で走るので、Eglot が手を離したときは、合流した CAPF を外して、元に戻します。

*なぜ、静的な並びは合流させないのか*

elisp、text、org、shell の並びは、 =cape-capf-super= で 1 つにまとめません。 =cape-capf-super= は、補完の開始位置が
違う CAPF を合流できません（ファイルや TeX は、シンボルと開始位置が違います）。まとめると、ファイルの補完が黙って
落ちます。Eglot と dabbrev は同じ開始位置で補うので、合流させても失うものがありません。

#+begin_src emacs-lisp
  ;;; completion/completion-capf.el --- モード別 CAPF 設定 -*- lexical-binding: t; -*-
  ;;
  ;; Copyright (c) 2021-2026
  ;; Author: YAMASHITA, Takao
  ;; License: GNU GPL v3 or later
  ;;
  ;; Category: completion
  ;;
  ;;; Commentary:
  ;;
  ;; モード別の `completion-at-point-functions'（CAPF）スタック。
  ;;
  ;; 本ファイルの責務:
  ;; - バッファローカルな CAPF 設定関数 `completion--set-capfs' を提供する
  ;; - emacs-lisp、prog、text、org、shell、repl の各 CAPF スタックを定義する
  ;; - 各スタックを対応するモードフックに登録する
  ;; - 正式な `completion-category-overrides' テーブルを所有する
  ;; - Eglot が管理するバッファでは、Eglot の候補に `cape-dabbrev' を合流させる
  ;;
  ;; 注意: 上の静的なスタック（elisp、text、org、shell）を `cape-capf-super' で 1 つに
  ;; まとめることはしない。`cape-capf-super' は補完の開始位置が違う CAPF を合流できず
  ;; （file や tex は symbol と開始位置が違う）、file 補完が静かに落ちるためである。
  ;; Eglot と dabbrev は同じ開始位置で補うので、合流させても失うものがない。
  ;;
  ;; 注意: `completion-category-overrides' はここでのみ設定する。
  ;; completion-core.el は意図的にこれを省いている。本ファイルは（completion-core.el で
  ;; 設定される）基本の orderless スタイルを、file、symbol、keyword、tex、dabbrev の
  ;; カテゴリ別ルールで拡張する。正となる情報源を 1 つに保つことで、後勝ちによる
  ;; 静かな衝突を防いでいる。
  ;;; Code:

  (defun completion--set-capfs (capfs)
    "Set `completion-at-point-functions' buffer-locally to CAPFS.
  Duplicates are dropped (the first occurrence wins), so stacks built by
  appending to the existing list stay idempotent when several hooks run."
    (setq-local completion-at-point-functions (delete-dups (copy-sequence capfs))))

  (defun completion--elisp-capfs ()
    "Install Emacs Lisp CAPF stack: symbol, file, and dabbrev sources."
    (completion--set-capfs '(cape-elisp-symbol cape-file cape-dabbrev)))

  (defun completion--prog-capfs ()
    "Augment the existing prog-mode CAPF stack with file and dabbrev sources."
    (completion--set-capfs (append completion-at-point-functions '(cape-file cape-dabbrev))))

  (defun completion--text-capfs ()
    "Install text-mode CAPF stack: dabbrev and file sources."
    (completion--set-capfs '(cape-dabbrev cape-file)))

  (defun completion--org-capfs ()
    "Install Org-mode CAPF stack: dabbrev, file, and TeX symbol sources."
    (completion--set-capfs '(cape-dabbrev cape-file cape-tex)))

  (defun completion--shell-capfs ()
    "Install shell-mode CAPF stack: file path and dabbrev sources."
    (completion--set-capfs '(cape-file cape-dabbrev)))

  (defun completion--repl-capfs ()
    "Augment the existing REPL CAPF stack with dabbrev source."
    (completion--set-capfs (append completion-at-point-functions '(cape-dabbrev))))

  (declare-function cape-capf-super "cape")
  (declare-function eglot-completion-at-point "eglot")
  (declare-function eglot-managed-p "eglot")

  (defvar-local completion--eglot-super-capf nil
    "The merged Eglot + dabbrev CAPF installed in this buffer, or nil.")

  (defun completion--eglot-capfs ()
    "Merge Eglot completion with `cape-dabbrev' while Eglot manages this buffer.
  Run from `eglot-managed-mode-hook', which fires on both enabling and
  disabling, so the merged CAPF is removed again when Eglot lets go."
    (if (eglot-managed-p)
        (when (and (not completion--eglot-super-capf)
                   (memq #'eglot-completion-at-point completion-at-point-functions))
          (require 'cape)
          (setq completion--eglot-super-capf
                (cape-capf-super #'eglot-completion-at-point #'cape-dabbrev))
          (setq-local completion-at-point-functions
                      (cons completion--eglot-super-capf
                            (remq #'eglot-completion-at-point
                                  completion-at-point-functions))))
      (when completion--eglot-super-capf
        (setq-local completion-at-point-functions
                    (remq completion--eglot-super-capf completion-at-point-functions))
        (setq completion--eglot-super-capf nil))))

  (add-hook 'emacs-lisp-mode-hook #'completion--elisp-capfs)
  (add-hook 'lisp-interaction-mode-hook #'completion--elisp-capfs)
  (add-hook 'prog-mode-hook #'completion--prog-capfs)
  (add-hook 'text-mode-hook #'completion--text-capfs)
  (add-hook 'org-mode-hook #'completion--org-capfs)
  (add-hook 'sh-mode-hook #'completion--shell-capfs)
  (add-hook 'eshell-mode-hook #'completion--shell-capfs)
  (add-hook 'ielm-mode-hook #'completion--repl-capfs)
  (add-hook 'comint-mode-hook #'completion--repl-capfs)
  (add-hook 'eglot-managed-mode-hook #'completion--eglot-capfs)

  ;; completion-category-overrides は defcustom（minibuffer.el）である。
  ;; 本ファイルが正式な所有者であり（Commentary 参照）、setter と型検証を尊重するため
  ;; setopt を用いる。
  (setopt completion-category-overrides
          '((file (styles basic partial-completion))
            (symbol (styles orderless))
            (keyword (styles orderless))
            (tex (styles basic))
            (dabbrev (styles basic))))

  (provide 'completion-capf)
  ;;; completion/completion-capf.el ends here
#+end_src

** completion-org-src.el — Org SRC Block Completion

Org のソースブロックの中でも、その言語に応じた補完がほしい。この要求に応えるのがここです。

[[file:../svg/07_capf_dispatch.svg]]

*どうやって言語を判定しているか*

=org-edit-special= で開く編集バッファは、その言語自身のメジャーモード（ =python-mode= など）を持ちます。
=org-src-mode-hook= で =derived-mode-p= によってそのモードを判定し、Python ブロックには Python の補完が、
Elisp ブロックには Elisp の補完が適用されます。

*4 つの関数の分担と、登録順の意味*

以前は 4 つのファイルに分けていましたが、どれも =org-src-mode-hook= に 1 つずつ関数を足すだけの小さな
モジュールで、公開するシンボルもありません。そこで 1 つのファイルにまとめ、責務は関数ごとに分けています。

- =completion--org-src-capfs= — 編集バッファのモード判定と CAPF スタックの選択（汎用）
- =completion--org-src-lang-capfs= — shell / SQL / Python の言語ごとの CAPF 選択
- =completion--org-src-corfu-setup= — corfu の遅延と接頭辞（バッファローカル）
- =completion--org-src-orderless-setup= — orderless のカテゴリ別スタイル（バッファローカル）

=add-hook= は関数をフックの先頭へ足すので、実行順は登録の逆になります。このファイルでは、汎用、言語別、
corfu、orderless の順に登録しているため、実行順は orderless、corfu、言語別、汎用です。言語別のスタックが
汎用より先に設定され、後から走る汎用の =completion--set-capfs= が重複を除くので、言語別の並びが保たれます。
*登録の並びを入れ替えないでください。*

*登録された関数と、設定される値*

| 関数 | 設定するもの |
|------|--------------|
| =completion--org-src-capfs= | 派生元のモードで、並びを選ぶ（ elisp → elisp 用、 prog → prog 用、ほかは text 用） |
| =completion--org-src-lang-capfs= | shell は「ファイル、 dabbrev 」、SQL は「 dabbrev 、ファイル」、Python は「既存の並びに、ファイル、 dabbrev を足す」 |
| =completion--org-src-corfu-setup= | =corfu-auto= を =t= 、 =corfu-auto-delay= を 0.1 秒、 =corfu-auto-prefix= を 1 、 =corfu-cycle= を =nil= |
| =completion--org-src-orderless-setup= | カテゴリ別のスタイル（ symbol 、 keyword 、 function 、 variable は orderless 。 file は basic と partial-completion 。 dabbrev は basic ） |

どれも =org-src-mode-hook= に登録され、ソースブロックの編集バッファの中だけに効きます。

*バッファローカルに設定する理由*

コーディング規則 6 は、 =defcustom= の変数には =setopt= を使うと定めています。ただし、規則 6 は大域の設定に
適用されるもので、ここは、ソースブロックの編集バッファの中だけに、グローバルな値に影響を与えずに上書きしたい
場面です。 =setopt= にはバッファローカル版がないので、 =setq-local= が唯一の正しい形です。大域の
=completion-category-overrides= を持つのは、 =completion-capf= です。

#+begin_src emacs-lisp
  ;;; completion/completion-org-src.el --- Org SRC 編集バッファ向けの補完設定 -*- lexical-binding: t; -*-
  ;;
  ;; Copyright (c) 2021-2026
  ;; Author: YAMASHITA, Takao
  ;; License: GNU GPL v3 or later
  ;;
  ;; Category: completion
  ;;
  ;;; Commentary:
  ;;
  ;; Org SRC 編集バッファ向けの補完設定。`org-src-mode-hook' に 4 つの関数を登録する。
  ;;
  ;; 本ファイルの責務:
  ;; - 派生したメジャーモードに応じて CAPF スタックを選択する（elisp → elisp-capfs、
  ;;   prog → prog-capfs、それ以外 → text-capfs）。`completion--org-src-capfs'
  ;; - shell、SQL、Python モードに対して、きめ細かいスタックを提供する。
  ;;   `completion--org-src-lang-capfs'
  ;; - コードブロック内での補完をより即応的にするため、`corfu-auto-delay' を 0.1 秒、
  ;;   `corfu-auto-prefix' を 1 に下げ、`corfu-cycle' を無効化する。
  ;;   `completion--org-src-corfu-setup'
  ;; - バッファローカルな `completion-category-overrides' を設定し、symbol、keyword、
  ;;   function、variable の各カテゴリで orderless を、file と dabbrev で
  ;;   basic/partial-completion を使わせる。`completion--org-src-orderless-setup'
  ;;
  ;; 注意（登録順）: `add-hook' は既定で先頭に追加するため、`org-src-mode-hook' での実行順は
  ;; 登録の逆になる。下では汎用、言語別、corfu、orderless の順に登録するので、実行順は
  ;; orderless、corfu、言語別、汎用である。言語別のスタックを設定した後に汎用のスタック
  ;; （`completion--org-src-capfs'）も続けて走るが、`completion--set-capfs' が重複を除くので、
  ;; 言語別スタックの並びは保たれ、`cape-file' と `cape-dabbrev' は重複しない。
  ;; 登録の並びを入れ替えないこと。
  ;;
  ;; 変数代入に関する注記: `corfu-auto'、`corfu-auto-delay'、`corfu-auto-prefix'、
  ;; `corfu-cycle'、`completion-category-overrides' はいずれも defcustom である。
  ;; コーディング規則 6 は defcustom への代入に `setopt' を要求するが、規則 6 は
  ;; グローバル設定に適用されるものである。ここでは、グローバル値に影響を与えずに
  ;; org-src-mode バッファ内でのみ *バッファローカル* な上書きを確立するため、意図的に
  ;; `setq-local' を用いる。`setopt' にはバッファローカル版が無いため、この用途では
  ;; `setq-local' が唯一かつ正しい形式である。グローバルな `completion-category-overrides'
  ;; の正式な所有者は completion-capf.el である。
  ;;; Code:

  (defun completion--org-src-capfs ()
    "Select the CAPF stack appropriate for the current Org SRC edit buffer.
  Dispatches to `completion--elisp-capfs' for Emacs Lisp, `completion--prog-capfs'
  for other prog modes, and `completion--text-capfs' as a fallback."
    (cond ((derived-mode-p 'emacs-lisp-mode) (completion--elisp-capfs))
          ((derived-mode-p 'prog-mode) (completion--prog-capfs))
          (t (completion--text-capfs))))

  (defun completion--org-src-shell-capfs ()
    (completion--set-capfs '(cape-file cape-dabbrev)))

  (defun completion--org-src-sql-capfs ()
    (completion--set-capfs '(cape-dabbrev cape-file)))

  (defun completion--org-src-python-capfs ()
    (completion--set-capfs (append completion-at-point-functions '(cape-file cape-dabbrev))))

  (defun completion--org-src-lang-capfs ()
    "Apply a language-specific CAPF stack for the current Org SRC edit buffer.
  Handles shell, SQL, and Python modes with dedicated stacks; returns nil for
  other languages so the generic `completion--org-src-capfs' stack applies."
    (cond ((derived-mode-p 'sh-mode 'shell-mode 'eshell-mode) (completion--org-src-shell-capfs))
          ((derived-mode-p 'sql-mode) (completion--org-src-sql-capfs))
          ((derived-mode-p 'python-mode) (completion--org-src-python-capfs))
          (t nil)))

  (defun completion--org-src-corfu-setup ()
    "Configure Corfu for responsive completion inside Org SRC edit buffers.
  Enables auto-completion, reduces delay to 0.1 s, lowers prefix threshold to 1,
  and disables cycling — all as buffer-local values that leave the global
  defcustom settings intact.  Uses setq-local because setopt has no buffer-local
  variant; see Commentary for the rationale."
    ;; バッファローカルな上書き: グローバルな defcustom の値を変えずに org-src-mode
    ;; バッファだけ高速な補完設定にしたいので、ここでは setq-local が正しい
    ;; （上の Commentary を参照）。
    (setq-local corfu-auto t)
    (setq-local corfu-auto-delay 0.1)
    (setq-local corfu-auto-prefix 1)
    (setq-local corfu-cycle nil))

  (defun completion--org-src-orderless-setup ()
    "Configure Orderless completion styles for the current Org SRC edit buffer.
  Sets `completion-category-overrides' buffer-locally so that symbol, keyword,
  function, and variable categories use Orderless, while file and dabbrev use
  basic/partial-completion.  Does not affect the global value owned by
  completion-capf.el.  Uses setq-local because setopt has no buffer-local variant."
    ;; バッファローカルな上書き: completion-capf.el が所有するグローバルな
    ;; completion-category-overrides の値には影響しない（上の Commentary を参照）。
    (setq-local completion-category-overrides
                '((symbol  (styles orderless)) (keyword (styles orderless))
                  (function (styles orderless)) (variable (styles orderless))
                  (file     (styles basic partial-completion))
                  (dabbrev  (styles basic)))))

  ;; 登録の並びを入れ替えないこと（Commentary の「登録順」を参照）。
  (add-hook 'org-src-mode-hook #'completion--org-src-capfs)
  (add-hook 'org-src-mode-hook #'completion--org-src-lang-capfs)
  (add-hook 'org-src-mode-hook #'completion--org-src-corfu-setup)
  (add-hook 'org-src-mode-hook #'completion--org-src-orderless-setup)

  (provide 'completion-org-src)
  ;;; completion/completion-org-src.el ends here
#+end_src

** completion-lsp.el — Eglot Lifecycle Cleanup

プロジェクトを切り替えたときに、不要になった Eglot サーバを止めるモジュールです。

=find-file-hook= と =project-switch-project-hook= で現在のプロジェクトのルートを調べ、前回と変わっていれば、
前のルート配下で動いている Eglot サーバを停止します。Eglot の公開 API（ =eglot-managed-buffers= 、
=eglot-current-server= 、 =eglot-shutdown= ）だけを使い、 =eglot--project= は =fboundp= で守っています。

補完用の CAPF 関数（ =eglot-completion-at-point= など）はここでは追加しません。それらは Eglot 自身が
接続したバッファで登録します。lsp-mode には対応しません。

*設定と動作*

- =completion-lsp-enable-p= （既定は =t= ）を =nil= にすると、この処理全体を止められます。
- =completion-lsp-on-project-switch= が、ファイルを開くたび（ =find-file-hook= ）と、プロジェクトを切り替えるたび
  （ =project-switch-project-hook= ）に、プロジェクトのルートを調べます。前回のルートと違えば、前回のルート配下の
  サーバを探して停止します。
- 停止の対象は、 =eglot-managed-buffers= から集めたサーバのうち、サーバのルートが前回のルート配下にあるものです。
  同じサーバは 1 回しか止めません。停止に失敗しても、メッセージを出すだけで、処理は続けます。

*注意*

- TRAMP のバッファ（リモートのファイル）は、対象外です。 =project-current= が、 =find-file= のたびにリモートの
  ホストでコマンドを実行してしまうためです。リモートのバッファは、記録しているルートも変えません。
- Eglot の内部の変数（ =eglot--servers= ）は使いません。 =eglot--project= は内部の関数ですが、 =fboundp= で守って、
  Emacs のバージョンの差に備えています。

#+begin_src emacs-lisp
  ;;; completion/completion-lsp.el --- LSP ライフサイクルの後始末 -*- lexical-binding: t; -*-
  ;;
  ;; Copyright (c) 2021-2026
  ;; Author: YAMASHITA, Takao
  ;; License: GNU GPL v3 or later
  ;;
  ;; Category: completion
  ;;
  ;;; Commentary:
  ;; プロジェクト切替時に、不要になった Eglot サーバを防御的に停止する。
  ;;
  ;; 内部変数 `eglot--servers' は使わず、公開 API の `eglot-current-server' +
  ;; `eglot-managed-buffers' で稼働中のサーバを調べる。
  ;; `eglot--project' は内部関数なので、Emacs のバージョン差に対して安全であるよう
  ;; `fboundp' でガードしている。
  ;;
  ;;; Code:

  ;; バイトコンパイル時の警告を避けるための宣言（実体は各パッケージ／ライブラリ側にある）。
  (declare-function project-root "project")

  (eval-when-compile (require 'leaf))

  ;; defcustom を定義する他のすべてのモジュールと規約を揃えるため defgroup を
  ;; 追加した。defgroup が無いと :group の参照が解決できず、バイトコンパイル時に
  ;; 警告が出る。
  (defgroup completion-lsp nil
    "LSP lifecycle cleanup helpers."
    :group 'completion)

  (defcustom completion-lsp-enable-p t
    "Enable LSP lifecycle cleanup."
    :type 'boolean
    :group 'completion-lsp)

  (defvar completion-lsp--current-project-root nil
    "The project root active when the last project-switch check ran.")

  (defun completion-lsp--project-root ()
    "Return the root directory of the current project, or nil."
    (when-let* ((project (project-current nil)))
      (expand-file-name (project-root project))))

  (defun completion-lsp--shutdown-stale-servers (old-root)
    "Shutdown Eglot servers whose root matches OLD-ROOT.

    Uses only public Eglot API (eglot-managed-buffers, eglot-current-server,
    eglot-shutdown) to avoid breakage from internal variable changes.
    eglot--project is guarded with fboundp for forward compatibility."
    (when (and (stringp old-root)
               (featurep 'eglot)
               (fboundp 'eglot-managed-buffers)
               (fboundp 'eglot-current-server)
               (fboundp 'eglot-shutdown))
      (let ((seen-servers (make-hash-table :test 'eq)))
        (dolist (buf (eglot-managed-buffers))
          (when (buffer-live-p buf)
            (with-current-buffer buf
              (when-let* ((server (ignore-errors (eglot-current-server))))
                (unless (gethash server seen-servers)
                  (puthash server t seen-servers)
                  (let ((server-root
                         (ignore-errors
                           (when (fboundp 'eglot--project)
                             (expand-file-name
                              (project-root (eglot--project server)))))))
                    (when (and server-root
                               (string-prefix-p old-root server-root))
                      (condition-case err
                          (eglot-shutdown server)
                        (error (message "[completion-lsp] failed to shut down stale server: %s"
                                        (error-message-string err))))))))))))))

  (defun completion-lsp-on-project-switch ()
    "Shutdown obsolete Eglot servers when switching projects.
  Remote (TRAMP) buffers are ignored: `project-current' would run commands on
  the remote host on every `find-file', and they must not reset the tracked root."
    (when (and completion-lsp-enable-p
               (not (file-remote-p default-directory)))
      (let ((new-root (completion-lsp--project-root)))
        (when (and completion-lsp--current-project-root
                   new-root
                   (not (string-equal completion-lsp--current-project-root new-root)))
          (completion-lsp--shutdown-stale-servers
           completion-lsp--current-project-root))
        (setq completion-lsp--current-project-root new-root))))

  (add-hook 'find-file-hook #'completion-lsp-on-project-switch)
  (add-hook 'project-switch-project-hook #'completion-lsp-on-project-switch)

  (provide 'completion-lsp)
  ;;; completion/completion-lsp.el ends here
#+end_src

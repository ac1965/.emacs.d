* 起動シーケンス

** 3フェーズの全体像

Emacs の起動は内部的に 3 段階に分かれてる。

- *Phase 1 (early-init.el)* — フレームが描画される前の最初期処理。
  =package.el= を無効化して、ディレクトリを整えて、GC を一時的に緩める。
- *Phase 2 (init.el)* — =straight.el= と =leaf= をブートストラップして、
  モジュールシステムを起動する手前の下ごしらえをする。
- *Phase 3 (modules.el)* — 74 本のモジュールを決められた順番でロードする。
  1 本コケても残りの 73 本は続く（delete-safety、後述）。

*Org を組み込みに戻した理由（§4）*

以前は =init.el= で =(straight-use-package 'org)= していたが、これは撤去した。理由は次のとおり。

- 使っている Org 関連パッケージ（ox-hugo、org-roam、org-modern 等）はどれも組み込み Org で動く。bleeding-edge な Org を要求するものはない。
- straight 版だと「組み込み Org の autoload に一度でも触れたら壊れる」という "mixed Org version" 問題を抱え込む。決定論的起動という原則にとって負債でしかない。
- straight が依存関係解決の過程で Org を勝手に clone してしまう問題があったので、 =straight-built-in-pseudo-packages= に =org= を追加して対処済み（設定は =early-init.el= 側、straight のブートストラップより前である必要がある）。

* modules.el — Delete-Safety の実装

=modules.el= は設定システムの司令塔。
一番大事なのは「1 本壊れても全体が止まらない」という delete-safety の保証で、
その核心が =condition-case= による各モジュールの隔離。

[[file:svg/02_condition_case.svg]]

- =error= だけを捕まえる。 =quit= (=C-g=) は意図的に伝播させる。
  ユーザーが中断したいときは中断できるようにしておく必要があるので。
- =my:modules-verbose= が非 nil なら各モジュールのロード時間をミリ秒単位で表示する。
- =my:modules-skip= にシンボルを入れておくと、そのモジュールを静かにスキップできる。
  たとえば =dev-docker= を使わないデバイスでは省略できる。
- =my:modules-extra= は =personal/user.el= が追記する。正規リストの後ろに追加される。
  ちなみにこれは =setopt= ではなく =setq= で代入する。理由は、personal オーバーレイが走る時点では
  まだ =defcustom= が評価されていない（ =modules.el= のロードより前）ため、 =setopt= を使うと
  =void-variable= になってしまうから。

#+begin_src emacs-lisp
;; modules.el の核心部分 — my/modules-load
(defun my/modules-load ()
  "Load all modules defined by `my:modules`, respecting options."
  (let* ((all (append my:modules my:modules-extra))
         (final (seq-remove (lambda (m) (not (modules--should-load-p m))) all))
         (skipped (seq-remove (lambda (m) (memq m final)) all))
         (ok 0) (ng 0)
         (failed '())
         (t0 (and my:modules-verbose (current-time))))
    (dolist (mod final)
      (let ((m0 (and my:modules-verbose (current-time))))
        (if (modules--require-safe mod)
            (setq ok (1+ ok))
          (setq ng (1+ ng))
          (push mod failed))
        (when my:modules-verbose
          (message "[modules] %-24s %s"
                   mod
                   (modules--format-seconds
                    (float-time (time-subtract (current-time) m0)))))))
    (when my:modules-verbose
      (message "[modules] loaded=%d skipped=%d failed=%d total=%s"
               ok (length skipped) ng
               (modules--format-seconds
                (float-time (time-subtract (current-time) t0)))))
    ok))
#+end_src

#+begin_quote
*以前との違い:* ここに載せていたのは =dolist= で回すだけの簡略版だったが、実装は
=modules--should-load-p= / =modules--require-safe= / =modules--format-seconds= の 3 つの
ヘルパーに分割された =my/modules-load= になっている。ロード成功・失敗・スキップの件数を
集計して起動完了時にまとめて報告する点が増えた（ =[modules]= プレフィックスで
loaded / skipped / failed の件数をまとめて出す 1 行サマリ）。 =condition-case= で =error= だけを捕まえて =quit= は伝播させる、という
delete-safety の核はそのまま。
#+end_quote

GC 管理は 3 つのモジュールが役割を分担している。

| 層 | ファイル | タイミング | 内容 |
|----+----------+------------+------|

** ~/.authinfo.gpg に必要なエントリ

#+begin_example
# Anthropic Claude API (utils-claude.el 用)
machine api.anthropic.com login apikey password sk-ant-...

# OpenRouter (aidermacs 優先バックエンド)

=login= フィールドは =:user= 引数に完全一致しないと =auth-source-search= が何も返さない。
不一致でもエラーにはならず黙って空を返すだけなので、「キーを書いたのに認識されない」ときは
まずここを疑う。

** after-init-hook 頼みだけじゃない、二段構えの安全策

=auth-gpg= が =dev-ai= よりも先に =modules.el= でロードされ、両者とも =after-init-hook= に
処理を登録している。ただし =add-hook= は APPEND を渡さない限り新しい関数をフックリストの
*先頭* に追加するため、同じ DEPTH（既定 0）のままでは「後から登録した関数ほど先に走る」
——つまり *ロード順の逆* になる。この前提を誤って「先に登録した auth-gpg の処理が先に走る」
と思い込んでいたのが後述の「dev-ai.el — aidermacs の認証タイミング」節で説明した実機バグの
原因で、現在は =dev-ai--setup-api-key= の登録に DEPTH =10= を明示し、既定 DEPTH（0）の
=auth-gpg--configure-sources= より確実に後で走るようにしてある。

#+begin_example
auth-gpg ロード → after-init-hook に configure-sources を DEPTH 0 で登録
dev-ai   ロード → after-init-hook に setup-api-key を DEPTH 10 で登録
  ↓ after-init-hook 発火（DEPTH の昇順で実行）
  #1 (depth 0):  auth-gpg--configure-sources → ~/.authinfo.gpg を auth-sources 先頭に追加
  #2 (depth 10): dev-ai--setup-api-key → auth-source-search が成功 ✓
#+end_example

DEPTH による順序保証に加えて、 =dev-ai--setup-api-key= 自身にも
=dev-ai--ensure-authinfo-in-sources= を仕込んであり、検索前に「 =auth-gpg-file= （未ロードなら
=~/.authinfo.gpg= にフォールバック）が =auth-sources= に入っているか」を自前でチェックして、
無ければ先頭に追加してキャッシュをクリアする。つまり *auth-gpg の実行が何らかの理由で
スキップされても* 、dev-ai 側だけで検索が成功するように二重に保険を掛けてある。

** auth-keychain.el — 独自バックエンドから組み込みへの置き換え

#+begin_quote

=⛔ Error excessive-lisp-nesting= 、そして =Command attempted to use minibuffer
while in minibuffer= が発生した。バックトレースを取ると、 =auth-source-backend-parse=
と =auth-keychain--make-backend= が交互に無限に呼び合っていた。

原因は =auth-keychain--make-backend= （ =auth-source-backend-parser-functions= に
登録される関数）の実装ミス。 =auth-source-backend-parse= はディスパッチャで、
=auth-source-backend-parser-functions= を先頭から順に試して最初に非nilを返した
関数の結果を使う。ところが =auth-keychain--make-backend= は、eieio の
コンストラクタで直接オブジェクトを組み立てる代わりに、このディスパッチャ自身を
再帰的に呼び出していた。呼び出すたびに =auth-source-backend-parser-functions= には
まだ =auth-keychain--make-backend= 自身が残っているため、二度と終わらない。

調査の過程で、この Emacs（32.0.50、開発版）には *組み込みの* macOS Keychain
バックエンド（ =auth-source-backends-parser-macos-keychain= ）が既に存在すると
判明した。 =security(1)= を独自に呼ぶ実装は、この組み込み機能が入る前に書かれた
ものだったと見られる。バグを個別に直すのではなく、独自実装を丸ごと廃止して
組み込みバックエンドへの委譲に置き換えた。
#+end_quote

*:host の意味づけがバックエンド種別で変わる罠:* 組み込みの macOS Keychain
バックエンドには =macos-keychain-internet= と =macos-keychain-generic= の
2種類があり、 =:host= の意味が異なる。

- =macos-keychain-internet= — =:host= は素直に =security find-internet-password -s HOST=
  の =-s= （サービス名）に渡る。 =auth-gpg= や =dev-ai= など他のバックエンドと同じ
  「 =:host= = 対象ホスト」という意味づけ。
- =macos-keychain-generic= — =:host= は =-c HOST= （Keychain の「creator」フィールド）に
  マップされ、 =-s= （サービス名）の方には代わりに =:port= を渡す必要がある。他のコードが
  素直に =:host= だけ渡すと *サイレントに何も見つからない* 。

このねじれのため =macos-keychain-internet= を採用し、Keychain エントリは
=security add-internet-password= で保存する必要がある（旧実装が使っていた
=add-generic-password= とは別物）。 =auth-keychain--startup-init= は
=(add-to-list 'auth-sources 'macos-keychain-internet t)= を呼ぶだけの薄いラッパーに
なり、 =auth-source-macos-keychain-search= の呼び出しは Emacs 本体に委ねる。

* orgx Layer — Auto-Tangle & Auto-Hugo

[[file:svg/10_orgtangle_hugo.svg]]

orgx 層は全部で 12 モジュール。 =my:modules= に入ってる正規モジュールは 8 つで、残る 4 つ
（ =orgx-typography= / =orgx-brain= / =orgx-roam-ui= / =orgx-citar= ）はオプション拡張として =my:modules-extra=
経由で足すかどうかを選ぶ形。 =orgx-roam-ui= は既定では外してある——理由は次の「Org の遅延ロード」参照。

** Org の遅延ロード

Org を組み込みに戻しただけでは、orgx 層に Org を無条件で読み込む経路が 5 つ残っていた。
すべて遅延化してある。

- =orgx-core= の =(leaf org :require t)= — :require t を削除。 =:custom= は Custom が
  値を先行登録し、 =:config= は leaf が =with-eval-after-load 'org= へ包む。
- =orgx-export= の =(leaf ox :straight nil :require t)= — 削除。 =ox= は =ox-hugo= が
  自身で require する。
- =orgx-export= の =(leaf ox-hugo :require t)= — :require t を削除。エクスポートは
  =org-hugo-export-wim-to-md= の autoload から起動する。
- =orgx-export= の =(leaf ob-mermaid :require t)= — leaf は導入のみ。
  =orgx-export--register-mermaid= を =with-eval-after-load 'org= に置き、org のロード時に
  require → =setopt= → 言語登録の順で実行する。
- =orgx-auto-tangle= と =orgx-auto-hugo= は、トップレベルで =(require 'org)= / =(require 'ob-tangle)=
  / =(require 'ox-hugo)= を *しない* 。代わりに =declare-function= でバイトコンパイラ向けの宣言だけ
  済ませておき、実際の =require= は関数が実行されるタイミング（フック発火時）まで遅らせる。

#+begin_quote
*以前との違い:* =orgx-export= 側の =ox-hugo= の =:require t= 削除は、実は README.org の
Changelog には「完了した」と書かれていたのに、実際のコードには反映されていなかった
（ =orgx-auto-hugo.el= 側は同じ理由で正しく遅延化されていたのに、こちらだけ直し忘れて
いたと見られる）。ドキュメント（Changelog）とコードが食い違っていた実例で、
=check_fboundp_guards.py= のような機械的検査ではこの種の乖離は検出できない
（ =fboundp= ガードの話ではないため）。修正済みで、今はコードも上記の通り。
#+end_quote

どちらのフックも、発火する時点で Org は必ずロード済みという前提が成り立つ
（ =orgx-auto-tangle= は =org-mode-hook= 経由でしか登録されないし、 =orgx-auto-hugo= の
=org-capture-after-finalize-hook= も同様）ので、この遅延化は安全 *だが、それはあくまで
プログラムから呼ばれる経路の話* 。

#+begin_quote
*落とし穴（実機で踏んだ）:* =ox-hugo= の =:require t= を外した直後、 =M-x
org-hugo-export-wim-to-md= のような直接呼び出しは autoload 経由で問題なく動くのに、
=C-c C-e= の対話的ディスパッチメニューに Hugo の項目が出なくなった
（ =C-c C-e H A= が選べない）。原因は =org-export-dispatch= が
=org-export-registered-backends= を直接見てメニューを組み立てる点で、この一覧への
登録（ =org-export-define-derived-backend= ）は =ox-hugo.el= が *実際にロードされた*
副作用として起きるのであって、個々のコマンドの autoload cookie では発生しない。
つまり「関数呼び出しの autoload」と「バックエンドのメニュー登録」は別物で、
後者は :require t を外すと起動時だけでなく *ずっと* 登録されないままになる。

対処として、 =org-export-dispatch= 自体に =:before= advice を付け、メニューを開く
直前にだけ =ox-hugo= を require するようにした（ =orgx-export--ensure-ox-hugo-before-dispatch= ）。
通常起動時のコストは避けたまま、対話的なディスパッチメニューでも Hugo が正しく
選べるようにしている。
#+end_quote

ただし、既定構成では起動直後のアイドル時間に =orgx-extensions= が =org-roam-db-autosync-mode=
を有効化するため、結局 Org はそこそこ早めにロードされる。org-roam を使わない構成
（ =my:modules-skip= に =orgx-extensions= を追加）なら、Org を本当に使うまで完全に遅延できる。

** orgx-auto-tangle

=after-save-hook= をバッファローカルに登録しているので =README.org= 以外には影響しない。
再帰ループ防止のため =orgx-auto-tangle--in-progress= をバッファローカルフラグとして使っている。

#+begin_src emacs-lisp
(declare-function org-babel-tangle "ob-tangle" (&optional arg target-file lang-re))
(defvar-local orgx-auto-tangle--in-progress nil)

(defun orgx-auto-tangle--maybe ()
  (when (and (orgx-auto-tangle--eligible-p)
             (not orgx-auto-tangle--in-progress))
    (require 'ob-tangle)
    (let ((orgx-auto-tangle--in-progress t)
          (org-confirm-babel-evaluate nil)
          (inhibit-modification-hooks t))
      (condition-case err
          (org-babel-tangle)
        (error (message "[orgx-auto-tangle] error: %s" (error-message-string err)))))))
#+end_src

#+begin_quote
*Emacs 31 での追加対策:* =README.org= は約 1.3 万行、tangle 先はおよそ 90 ファイル。保存が
連続すると（ =auto-save-visited-mode= に加えて明示の =C-x C-s= が重なるなど）全 tangle が
2 回走ってしまうことがあった。 =timeout.el= の =timeout-throttle= で一定間隔内の連続呼び出しを
1 回にまとめている。実行中フラグ自体は非再入性の担保として引き続き必要（スロットリングは
頻度制限であって非再入性の保証ではないため）。
#+end_quote

** orgx-auto-hugo

=after-save-hook= ではなく =org-capture-after-finalize-hook= を使う。
キャプチャ編集中の自動保存で ox-hugo がトリガーされると未完成エントリがエクスポートされて
しまうため。 =org-note-abort= が非 nil なら（ =C-c C-k= でキャンセルされた場合）エクスポートを
スキップする。 =ox-hugo= のロードも同様に、トップレベルの =require= ではなく関数内部まで遅延している。

*確定前の手動ブラウザプレビュー:* =org-capture-mode-map= に =C-c C-p=
（ =orgx-auto-hugo-preview-capture= ）を割り当ててある。 =org-hugo-export-wim-to-md=
は使わない — キャプチャ対象ファイルが =#+HUGO_BASE_DIR= を持っていることが多く、
一時ディレクトリへの動的束縛より優先されて実 content へ書き出されてしまう危険があるため。
代わりに =org-export-as= を SUBTREEP 付きで直接呼び、現在のエントリだけをディスクに触れず
文字列化する。結果はキャプチャセッションごとの使い捨てスクラッチファイル（保持先は
バッファローカル変数ではなく =org-capture-put= のセッションプロパティ。バッファは確定・中断の
どちらでもフック前後に kill されうるため）に書き出し、そこで =markdown-preview-mode= を
有効化する。セッション終了時（確定・中断どちらでも）は =orgx-auto-hugo-preview--cleanup= が
スクラッチディレクトリを削除する。

*落とし穴（実機で踏んだ）:* =markdown-preview-mode= はブラウザへの更新送信
（スクロール同期）でプレビューバッファの *ウィンドウ* を参照する。 =find-file-noselect=
だけで作った、一度も表示されていないバッファに対して呼ぶと "Wrong type argument:
number-or-marker-p, nil" で失敗する（スクラッチファイル自体は正しく書き込まれるが、
送信だけ失敗する）。対処として、更新中だけスクラッチバッファを実ウィンドウに
=pop-to-buffer= し、直後にフォーカスをキャプチャバッファへ戻してタイピングを
妨げないようにしている。

** orgx-citar.el — citar / org-cite による文献引用管理

=citar= を =org-cite-insert-processor= / =org-cite-follow-processor= /
=org-cite-activate-processor= すべてのバックエンドとして登録する薄いモジュール。
=citar-embark= を =:after (citar embark)= で連結し、 =citar-embark-mode= を有効化して
=embark-act= 経由の文献アクション（開く・引用挿入など）を追加する。

=orgx-brain= と同じく =my:modules= には現れず、 =personal/user.el= が
=my:modules-extra= 経由で足すオプション拡張。理由も同じで、Org を起動直後に
引き込む正規モジュールを増やしたくないため。

*my:d:org-biblio の新設:* =citar-bibliography= の初期実装はホームディレクトリを
直書きした固定パス（ =~/org/roam/biblio/gov-standards.json= ）だった。orgx-core.el
の他の派生パス変数（ =my:d:org-journal= / =my:d:org-roam= / =my:d:org-pictures= ）に
揃え、 =my:d:org-biblio= （ =my:d:org= 配下、 =my/ensure-directory-exists= でディレクトリ
作成も保証）を新設してこれを置き換えた。personal 層でのパス上書き（macOS/WSL の
分岐など）が =my:d:org= 系のどの変数にも一律で効くようにするための、既存の
「上書きの契約」（ =orgx-core= 節冒頭のコメント参照）に合わせた対応。

#+begin_quote
*落とし穴（実機で踏んだ）:* 初版は =citar-bibliography= と =org-cite-global-bibliography=
も =:custom= に含めていたが、起動時に =⛔ Error (leaf): Attempt modify list= が出て
両変数とも設定されなかった。原因は leaf 内部の =leaf-normalize-list-in-list= —
=:custom= のペアは =(SYM . VALUE)= という真の dotted pair か、 =(SYM . 'quoted-value)=
のような特別扱いされる形でなければならず、 =(citar-bibliography . (list
(expand-file-name "gov-standards.json" my:d:org-biblio)))= のように任意の関数呼び出し
式を値にすると、Lisp リーダはこれを単なる 3 要素の proper list
=(citar-bibliography list (expand-file-name ...))= として読む。leaf はこれを
「複数の変数に同じ値を配る省略記法」（ =((a b c) . d) => ((a . d) (b . d) (c . d))= ）
と誤認し、 =citar-bibliography= ・ =list= ・ =expand-file-name= ・ =my:d:org-biblio=
を別々の変数として =nil= に =customize-set-variable= しようとして失敗する。

これは =org-todo-keywords= / =org-refile-targets= / =org-capture-templates= を
=:custom= ではなく =setq= に置いている、orgx-core 節および「setopt vs setq」節の
コーディング規則 §6 の例外と同じ種類の問題。値が実行時評価式（ =expand-file-name= の
呼び出しなど）を含む defcustom は =:custom= に置けない。対処として
=citar-bibliography= と =org-cite-global-bibliography= を =:config= 内の =setopt=
に移した。 =:custom= の生成コードは常に =:config= の本体より前に展開されるため、
=org-cite-global-bibliography= （ =citar-bibliography= の値をそのまま使う）を
=:custom= に残すと =citar-bibliography= 代入前の古い値を読んでしまう——この2つは
まとめて =:config= に置き、代入順序も保証する必要がある。
#+end_quote

** キー検索は :init ではなく after-init-hook で

以前は =:init= （モジュールロード時）で API キーを検索していたが、その時点ではまだ
=~/.authinfo.gpg= が =auth-sources= に追加されておらず、常に "no key found" になっていた。
=after-init-hook= に移したうえで、auth Layer の節で触れた =dev-ai--ensure-authinfo-in-sources=
による自前チェックも加えた。

#+begin_quote
*落とし穴（実機で踏んだ）:* 上の対処だけでは直らなかった。 =add-hook= は APPEND 引数を
渡さない限り新しい関数を *フックリストの先頭* に追加するため、同じ DEPTH（既定 0）内では
「後から登録した関数ほど先に走る」。 =auth-core= （ =epa-file-enable= を呼ぶ）と =auth-gpg=
（ =~/.authinfo.gpg= を =auth-sources= に追加する）はどちらも =my:modules= 上では
=dev-ai= より前にロードされるが、3 つとも =after-init-hook= への登録時に DEPTH を
指定していなかったため、実際の実行順は「ロード順」ではなく「登録順の逆」になっていた。
結果、 =dev-ai--setup-api-key= が =auth-core--startup-init= より *先に* 走り、
epa-file が未初期化のまま =auth-source-search= が =~/.authinfo.gpg= を読みに行くため
復号に失敗し、"No API key found" の警告が出る——しかしファイル自体は（復号できないまま）
開かれる、という一見矛盾した挙動になっていた。design_spec.org のこの節が「実行順序に
依存しない」と書いていたのは実装が追いついていなかったための誤りで、現在は下記の対処で
実際に順序非依存になっている。

対処として =dev-ai--setup-api-key= の登録に DEPTH =10= を明示した
（ =(add-hook 'after-init-hook #'dev-ai--setup-api-key 10)= ）。DEPTH は
=personal/ac1965.el= の =ac1965--bind-leader-keys= と同じ仕組みで、既定 DEPTH（0）の
フックがすべて走り終えたあとに実行されることを、モジュールのロード順に関係なく保証する。
=dev-ai--ensure-authinfo-in-sources= は =auth-gpg--configure-sources= の実行結果に
頼らない自前の安全策として引き続き残してあるが、 =epa-file-enable= 自体は
=auth-core--startup-init= 側でしか行わないため、DEPTH による実行順の保証が本質的な修正。
#+end_quote

* personal/ Layer — マシン固有オーバーレイ

=lisp/= 配下が「共有ポリシー」なら、 =personal/= は「このユーザー・この機械でしか意味を
持たない設定」の置き場。フォント、API キーの参照先、macOS 固有の挙動などを =lisp/= に
混ぜると他の環境で不可解な動きをするので、境界をはっきり分けてある。

| 特性 | 内容 |
|------+------|
| バージョン管理 | 共有コミットには含めない（各自でカスタマイズする前提） |
| 編集の安全性 | 変更しても他ユーザーには影響しない |
| ロード順 | =init.el= §8（ =modules.el= を require する §9 より *前* ） |

ロード順が「モジュールより前」というのが地味に重要で、 =my:modules-extra= への
追記や =my:d:org*= 系パス変数の上書きが、後続の =defvar= に対して先勝ちできるのは
この順序があってこそ。

| ファイル | 目的 |
|----------+------|
| =personal/user.el= | 全マシン共通の個人設定。ロケール初期化、WSL 判定 =my:wsl-p= 、デバイスファイルの読み込み分岐 |
| =personal/ac1965.el= | ログイン名に対応する識別情報・パス上書き・フォント・UI/LSP スイッチ |
| =personal/device-darwin.el= | macOS 固有: IME（sis）、マウス／トラックパッド、Apple Music 操作 |
| =personal/device-wsl.el= | WSL 固有: クリップボード連携、既定ブラウザ、Explorer 連携 |
| =personal/personal-messages.el= | macOS Messages.app のアーカイバ（org-roam へ） |
| =personal/personal-ai.el= | Org Babel の =claude= 言語と、対話的な Claude 連携コマンド |

** personal/user.el — 共通オーバーレイと my:modules-extra

全マシンで読み込まれる唯一のファイル。ここでやってることは主に 3 つ。

- =my:modules-extra= に =ui-visual-aids= / =orgx-typography= / =orgx-brain= / =ui-macos= を追記する。
  =orgx-roam-ui= はあえて入れていない。理由は auth Layer の節でも触れた「Org の遅延ロードを
  崩す」問題と同じで、 orgx の節を参照。
- =set-language-environment "Japanese"= → =prefer-coding-system 'utf-8= の順で呼んで、
  日本語ファイル検出のためのコーディングシステム優先順位を整える。 =set-locale-environment=
  だけでは Emacs 内部の優先順位リストまでは変わらないので、この 2 段構えが必要。
- =my:wsl-p= を定義して、 =device-<system-type>.el= か =device-wsl.el= かを振り分ける。
  WSL 上の =system-type= は素の Linux と同じ =gnu/linux= になってしまうので、
  =system-type= だけでは判定できず、環境変数 =WSL_DISTRO_NAME= を見て判定している。

#+begin_quote
*落とし穴:* =personal-messages= の自動アーカイブは =with-eval-after-load 'org= で
Org 準備完了まで遅延させたうえで、 =run-with-idle-timer= の REPEAT 引数に =600= （10 分）

** personal/device-darwin.el / device-wsl.el — OS ごとの分岐

=my:wsl-p= の判定結果で、どちらか一方だけがロードされる（両方同時にロードされることはない）。

*** device-darwin.el

- IME 切替は =sis= （smart-input-source）。 =macism= の有無にかかわらず =sis= 自体は
  常にロードする。理由は nano-modeline の IME インジケータが =sis--current= を必要と
  するため。 =macism= が実際に見つかったときだけ ISM とグローバルモードを有効化する。
- Logitech MX Ergo S 向けにスクロール量・慣性・マージンを調整。
- AppleScript 経由で Apple Music を操作するコマンド群と、それをまとめた
  =hydra-apple-music= （ =M-SPC a a= ）。

*** device-wsl.el

リーダーキーを =M-SPC= から =C-c SPC= へ *丸ごと張り替えている* 。Windows 側で Alt+Space が
システムメニューのショートカットと衝突しやすく、人間工学的にも押しにくいという理由。

#+begin_quote
*以前との違い（実機で踏んだバグ）:* このドキュメントには以前、「 =ui-leader--bind-root= 等は
本ファイルより前にロード済みだから、 =keymap-global-unset= で旧バインドを解除してから
=setopt ui-leader-key= して張り直せばよい」と書いてあった。これは *前提が逆* だった。

実際のロード順は =init.el= §8（ personal オーバーレイ）→ §9（ =(require 'modules)= ）で、
=device-wsl.el= は =personal/user.el= の内部から §8 の時点で同期的にロードされる。一方
=ui-leader.el= は =ui= 層のモジュールなので §9 の =modules.el= 経由でしか読み込まれない。
つまり =device-wsl.el= のトップレベルが評価される時点では =ui-leader-key= も
=ui-leader-map= も =boundp= ですらなく、旧実装の =(when (and (boundp 'ui-leader-key) ...) ...)=
は条件不成立で *黙ってスキップ* されていた。その後 §9 で =ui-leader.el= がロードされ、
=ui-leader--bind-root= が既定値 =M-SPC= で結線して終わり——つまりリーダーキーは
=C-c SPC= に切り替わらず =M-SPC= のまま残っていた。デバッガにも警告にも出ない、
静かな不具合だった。

対処として、トップレベル直書きをやめ、 =(with-eval-after-load 'ui-leader ...)= で
「 =ui-leader= がロードされ =ui-leader--bind-root= が =M-SPC= で一度結線した *直後* 」に
確実に実行されるよう変更した。これなら =personal/user.el= → =modules.el= という実際の
ロード順序に依存せず、常に「結線の後」に上書きできる。ちなみに =utils-ime.el= の

* 命名規則と変数代入ポリシー

** 命名規則

| プレフィックス | スコープ | 例 |
|----------------+----------+----|
| =my/= | 公開インタラクティブコマンド | =my/eww-search=, =my/auth-gpg-verify= |
| =<module>-= | モジュール公開 API | =core-treesit-install-all=, =ui-font-apply= |
| =<module>--= | モジュール内部実装 | =core-native--collect=, =modules--require-safe= |
| =my:d:*= | パス / ディレクトリ変数 | =my:d=, =my:d:var=, =my:d:org= |
| =my:modules= | 正規リスト定数 | =defconst= で定義。変更禁止 |

禁止パターン: =my/<topic>--= の複合形。公開名前空間 (=my/=) とプライベートスコープ (=--=) を混ぜてはいけない。

** setopt vs setq

| 使うべき形 | 対象 | 補足 |
|------------+------+------|
| =setopt= | =defcustom= 変数 | セッターと型チェックを通す |
| =setq= | =defvar=, 内部状態変数 | セッターが不要な場合 |
| =setopt= (=:config= 内) | 実行時評価が必要な =defcustom= パス | =:custom= では式評価不可 |
| =setq-local= | バッファローカルな =defcustom= 上書き | Makefile の =indent-tabs-mode= など |
| =customize-save-variable= | セッションをまたいで永続化が必要な =defcustom= | =personal-messages-last-archived= など |

=setq= が正解な =defcustom= 例外は、次の 3 つに限定される: =org-todo-keywords= 、
=org-refile-targets= 、 =org-capture-templates= 。いずれもバッククォートや =(function ...)=
による実行時評価を含む値を持つため、 =setopt= の型チェッカが値の完全な評価前に誤検知してしまう。
=:custom= や =:pre-setq= に移すこともできない。

#+begin_quote
*注意（以前との違い）:* =org-roam-db-connector= は setq 例外ではなく、現在は普通に =setopt=
で設定している（Emacs 31.0.50 で =sqlitep= の挙動が変わったことへの対応として、 =:config= 内で
=setopt org-roam-db-connector ...= と明示的に固定している）。また =org-agenda-files= は setq で
代入するが、これは型チェッカ回避のためではなく、「モジュールロード時は inbox.org だけの
フォールバック値、 =after-init-hook= で完全な一覧に差し替える」という 2 フェーズ構成のための
別理由による setq なので、上の 3 つの例外とは性質が違う。
#+end_quote

* Changelog について — Fix ID 方式は廃止済み

以前はここに =Fix A→CJ= のようなコード付きの修正一覧を置いていたが、README.org 側で
Changelog を一度リセットし、コード中のコメントや散文からも Fix ID 参照（ =[Fix BZ-1]= や

参照する運用はやめて、変更理由は該当箇所の Commentary に直接書き、変更履歴そのものは

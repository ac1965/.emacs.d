* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

これは、Org Mode と Babel を使ったリテラルプログラミング方式の Emacs 設定です。

普通の Emacs 設定は =.el= ファイルの集まりですが、この設定では =README.org= と =org/= 配下の
Org 文書がすべての出発点になります。ここに書いたソースブロックが tangle され、 =.el= ファイルとして
書き出されるという仕組みです。

[[file:svg/tangle-flow.svg]]

*なぜこの方式なのか*

設定が育つほど、「なぜこう書いたのか」が失われていきます。コメントに残しても、コードと
説明が別々に古びていくのが普通です。説明とコードを同じ節の同じソースブロックに同居させ、
=.el= を生成物と割り切ってしまえば、説明とコードが食い違うこと自体が構造的に起こり
えなくなります。設計の意図を書き残す場所と、実際に動くコードの場所が、同じ一箇所になる
わけです。

この「一箇所」は、ファイル 1 枚ではなく、同じ節のことです。設定の正本は =README.org= と =org/<層>.org= 、
補助スクリプトの正本は =org/tools.org= で、どれも説明とコードを同じ節に置きます。 =.el= と
=scripts/= は、この 2 つの Org 文書から tangle される生成物です。正本が複数の文書に
分かれても、説明をコードから切り離さない限り、この性質は保たれます。

*設計の柱*

- *決定論的な起動* — 同じ入力からは、いつでも同じ結果が得られること
- *明示的な依存関係* — 暗黙の自動探索はしない。何がいつ読まれるかを常に追えること
- *削除しても壊れない構成* — どのモジュールを消しても、残りは動き続けること
- *組み込み優先* — Emacs 31 の組み込み機能があるなら、自作の等価物より必ずそちらを使う
- *長期的な保守性* — 数年単位で育て続けられること
- *LSP バックエンド非依存* — eglot / lsp-mode を差し替え可能にすること（呼び出しは =dev-lsp-bridge= のファサードを通す）

** Clone and First Steps
:PROPERTIES:
:CUSTOM_ID: clone-and-first-steps
:END:

リポジトリは https://github.com/ac1965/.emacs.d です。 =git clone= した直後は
Org 文書（ =README.org= と =org/*.org= ）しか設定の実体がありません。 =early-init.el= 、
=init.el= 、 =lisp/= 、 =personal/= 、 =scripts/= 、 =Makefile= はすべてこれらからの tangle 生成物で、
=.gitignore= 対象だからです。そのため、clone のあとに *tangle する* 作業が必須になります。

1. 既存の =~/.emacs.d= があれば退避してから、clone します。

   #+begin_example
   mv ~/.emacs.d ~/.emacs.d.bak        # 既存の設定がある場合のみ
   git clone https://github.com/ac1965/.emacs.d ~/.emacs.d
   cd ~/.emacs.d
   #+end_example

2. 初回の tangle を行います。この時点では =Makefile= がまだ無いので、 =make= ではなく
   生の Emacs バッチコマンドを使います（理由は [[#tangling][Tangle]] の「初回ブートストラップ」を参照）。

   #+begin_example
   emacs -Q --batch --eval '(require (quote ob-tangle))' \
                     --eval '(dolist (f (append (list "README.org") (directory-files "org" t "[.]org$"))) (org-babel-tangle-file f))'
   #+end_example

3. 以後は =make reload= で再生成します（ =clean= + =tangle= + =check-cookies= ）。

   #+begin_example
   make reload
   #+end_example

4. Emacs を起動する。初回起動は、straight.el による外部パッケージの取得と
   ネイティブコンパイルが走るため、ネットワーク接続が必要で時間もかかります。
   途中でウィンドウが固まったように見えても、終わるまで待ってください。
   起動に失敗した場合は、 =*Messages*= と =*Warnings*= の内容を確認します。

5. 自分用の設定を =personal/= に合わせます。 =personal/user.el= 、 =personal/device-darwin.el=
   などは本人（ac1965）向けの内容を含む tangle 生成物です。そのまま使わず、
   README.org の [[file:org/personal.org::#personal-config][Personal Configuration]] 節にある該当ブロックを自分の環境向けに
   書き換えてから =make reload= してください。 =personal/= 自体を直接編集しても、
   次の tangle で上書きされます。

6. 秘密情報（API キー、パスワード等）は設定に書かず、 =pass= + GnuPG や
   auth-source に置きます（[[#prerequisites][Prerequisites]] の推奨ツールを参照）。

*注意*

- =.var/= は履歴などのランタイム状態です。消すと困るので残します。キャッシュ（ =my:d:cache= 、
  リポジトリの外の =$XDG_CACHE_HOME/emacs/= 、なければ =~/.cache/emacs/= ）は消しても
  自動的に作り直されます。
- 設定を変えるときは、生成物（ =.el= ）ではなく必ず README.org を編集します。

** Emacs Version Numbers
:PROPERTIES:
:CUSTOM_ID: emacs-version-numbers
:END:

Emacs のバージョンは =メジャー.マイナー.リビジョン= の形で表されます。たとえば
=32.0.50= なら、メジャーが 32、マイナーが 0、3 つ目が 50 です。

| 表記             | 意味                                                         |
|------------------+--------------------------------------------------------------|
| =30.1= 、 =31.1= | 安定版のリリース。2 要素で、マイナーが 1 以上になる          |
| =31.0.50=        | 開発版（ =master= ）。次の 31 リリースに向けた開発中の状態   |
| =31.0.90=        | プレテスト版。リリース直前の試験版で、 =.91= 、 =.92= と続く |
| =32.0.50=        | 31 の枝を切ったあとの =master= 。次の次の開発版              |

- *3 つ目が 50* ... 開発版（ =master= ）です。毎日のように変わるので、同じ =32.0.50= でも
  コミットが違えば中身も違います。
- *3 つ目が 90 以上* ... リリース前のプレテストです。90 から始まり、番号が進むほど
  正式版に近づきます。
- *2 要素* （ =31.1= など）... 正式リリースです。 =31.1= の次は、バグ修正版の =31.2= になります。

*本設定が対象とする版*

本設定は Emacs 31 を対象にしており、作者の環境は =32.0.50= （ =master= ）です。
[[#prerequisites][Prerequisites]] の表のとおり、同じ =32.0.50= でもコミットで挙動が変わるため、
問題を報告するときはバージョン番号だけでなくコミットも併記してください。

*自分の Emacs のバージョンを調べる*

#+begin_example
M-x emacs-version
#+end_example

Lisp からは =emacs-major-version= と =emacs-minor-version= で読めます。本設定のバージョン
ガードも、 =(>= emacs-major-version 31)= のようにこれらで判定しています。

** Architecture
:PROPERTIES:
:CUSTOM_ID: architecture
:END:

[[file:svg/emacs_config_layer_architecture.svg]]

設定全体は 10 層に分かれています。各層はそれぞれ固有の責務を持ち、依存関係は必ず一方向にしか
流れません。

#+begin_example
layer 10: personal      (ユーザー固有。下位層を変更してはならない)
layer  9: utils         (汎用ユーティリティ)
layer  8: dev           (言語モード、LSP、AI 支援)
layer  7: vcs           (Magit、Forge、diff-hl)
layer  6: orgx          (Org 拡張)
layer  5: completion    (vertico/corfu/consult/embark)
layer  4: auth          (auth-source、EasyPG)
layer  3: ui            (テーマ、フォント、ウィンドウ)
layer  2: core          (ランタイム基盤 + ポリシー)
layer  1: early-init    (package.el の無効化、GC 最適化)
#+end_example

*なぜ層に分けるのか*

Emacs の設定が壊れるときの典型は、「A を直したら、まったく関係ないと思っていた B が動かなく
なった」というパターンです。原因のほとんどは、依存関係が双方向に絡まっていることにあります。

そこで、層の順序を固定し、依存は下向きにしか流さない、というルールを置いています。上の層は
下の層を頼ってかまいませんが、下の層は上の層のことを知りません。これだけで、ある層に手を入れたときの
影響範囲は「その層と、それより上」に収まります。

ロード順は、上の一覧を下（layer 1）から上（layer 10）へたどった順です。これがそのまま依存の向きになります。

ただし personal だけは例外です。依存の向きでは最上位ですが、 =personal/user.el= と
=personal/<ユーザー名>.el= は、先に =my:modules-extra= や各種変数を決めておく必要があります。
そのため =init.el= のステップ 9 で、 =lisp/modules.el= （ステップ 10）より前に読み込まれます。
それ以外の =personal-*.el= は、 =user.el= が必要に応じて読み込みます（Org のロード後やアイドル時など）。

*守るべき不変条件*

- 上位層は下位層に依存してよい
- 下位層は上位層に依存してはならない
- 依存関係の自動探索は行わない
- すべての副作用は明示的である
- LSP バックエンド（eglot / lsp-mode）は =core-switches= で選択する

最後の一つは、この不変条件の効き目がよく分かる例です。 =core= 層にいる =core-switches= は
登録簿だけを持ち、バックエンドの名前を知りません。 =dev= 層の =dev-lsp-bridge= と =ui= 層の
=ui-bundles= が、自分から登録します。下位層から上位層への依存を作らずに切り替えを実現しています。
詳しくは =core-switches.el= の設計ノートを参照してください。

** Directory Layout
:PROPERTIES:
:CUSTOM_ID: directory-layout
:END:

リポジトリの構成は次のとおりです。

#+begin_example
.emacs.d/
├── README.org   (設計と設定の真実の源)
├── org/         (層ごとの真実の源。boot / core / ui / auth / completion / orgx / dev / vcs / utils / personal、補助スクリプトの tools)
├── Makefile     (README.org から tangle される)
├── early-init.el  (org/boot.org から tangle される)
├── init.el        (org/boot.org から tangle される)
├── lisp/
│   ├── modules.el
│   ├── core/
│   ├── ui/
│   ├── auth/
│   ├── completion/
│   ├── orgx/
│   ├── vcs/
│   ├── dev/
│   └── utils/
├── personal/    (ユーザー／デバイス固有のオーバーレイ)
├── scripts/     (lint・リロード・エクスポート・デモ撮影用のヘルパー。tangle 生成物)
├── svg/         (図のソース .dot/.mmd と、描画済みの .svg)
├── .var/        (ランタイム状態)
└── .etc/        (外部リソース)
#+end_example

=README.org= 、 =org/*.org= と =svg/*.svg= 、 =puppeteer-config.json= を除くファイルは、すべてこれらの Org 文書
から tangle される生成物です（ =svg/*.svg= は =make diagrams= で描画してコミットします）。直接編集しても、次の tangle で上書きされます。

| ディレクトリ | 役割 |
|-------------+------|
| =lisp/=     | モジュールのソースコード。 =lisp/modules.el= がローダのエントリポイント |
| =personal/= | ユーザー／デバイスのオーバーレイ（ =modules.el= より前に =init.el= が読み込む） |
| =.var/=     | ランタイム状態（パッケージが書き出すデータ） |
| キャッシュ（ =my:d:cache= ） | 一時キャッシュ。リポジトリの外の =$XDG_CACHE_HOME/emacs/= （なければ =~/.cache/emacs/= ）にあり、削除しても自動的に再生成される |
| =scripts/=  | =check_emphasis.py= などの Python ヘルパー（ =Makefile= から呼ばれる）、デモ画像の撮影スクリプト（ =demo-layout.el= 、 =shot.sh= 、 =compose.py= ）、キーバインド一覧 SVG の生成（ =cheatsheet.el= ） |
| =svg/=      | 図のソース（ =.dot= / =.mmd= ）と描画済みの =.svg= |
| =.etc/=     | no-littering の設定系ファイル（ =custom.el= 等） |

*状態ファイルを 3 つに分ける理由*

=.var/= 、キャッシュ（ =my:d:cache= ）、 =.etc/= を分けているのは、「消していいもの」と「消すと困るもの」を
はっきりさせるためです。キャッシュは消しても自動的に作り直されます。 =.var/= には履歴や
セッションなど、消すと復元できないものが入ります。トラブル時にどこを消せば安全かが、
ディレクトリ名だけで判断できる、という状態を目指しています。

** Layer Definitions
:PROPERTIES:
:CUSTOM_ID: layers
:END:

ここからは各層の責務を順に見ていきます。

*** core

ランタイムの土台です。最下位の機能層で、他のすべての層がこれに依存します。

責務:

- ネイティブコンパイルの警告の収集・診断・報告（ =core-native= 。 =eln-cache= の配置は =early-init.el= ）
- Tree-sitter 文法の管理（ =core-treesit= ）
- 履歴とセッション（ =core-history= ）、古いバックアップの削除（ =core-persistence= ）、
  自動保存とバックアップ（ =core-autosave= ）、編集まわりの既定（ =core-editing= ）
- dired の dirvish への置き換え（ =core-dired= ）
- 明示的な契機での GC（ =core-gc= ）と OS ごとの修飾キー変数・初回フレーム用ヘルパー（ =core-runtime= ）
- custom-file の管理（ =core-custom= ）と LSP/UI バックエンドの選択（ =core-switches= ）

*core に入れないもの*

ディレクトリ構成と =load-path= の構築は、core ではなく =early-init.el= と =lisp/modules.el=
の仕事です。core モジュールがロードされる時点では、これらは既に整っている前提になります。

また、core が ui 層に依存することは禁止です。「見た目のために core をいじる」を許すと、
層の順序が意味を失うためです。

*** policy

グローバルな編集ポリシーです（core 層の一部としてロードされます）。

責務:

- 空白・行末空白のルール
- インデント標準とタブポリシー
- エディタの安全制約（ =require-final-newline= 等）

policy は「どう書くか」を決めるだけの層なので、UI やパッケージ機能を有効化してはいけません。

*** ui

見た目と操作感を担当します。

責務:

- テーマとフォント（テーマは =my:use-ui= で決まる。 =nano= / =doom-nano= なら nano、 =doom= なら
  doom-themes のテーマ、 =none= なら Emacs の既定）
- ウィンドウ挙動
- UI ヘルパーとリーダーキー基盤
- UI バンドル（doom / nano / doom-nano）を =core-switches= の登録簿へ登録する（ =ui-bundles= ）

[[file:svg/emacs_keybindings_cheatsheet.svg]]

*** completion

補完フレームワークとミニバッファの使い心地を担当します。

責務:

- ミニバッファ UI（vertico、marginalia）
- ポップアップ補完（corfu、cape）
- 検索とナビゲーション（consult、embark）
- アイコン統合（nerd-icons、kind-icon）
- Org SRC ブロック内での補完統合

*completion-org-src について*

Org のソースブロックの中でも、その言語に応じた補完がほしい — この要求に応えるのが
=completion-org-src= です。ブロックの検出、言語ごとの CAPF 選択、corfu との統合、
orderless フィルタの適用を、 =org-src-mode-hook= に登録する 4 つの関数で協調させています。

*** auth

認証とシークレットの管理です。

責務:

- =auth-source= バックエンドの設定（ =auth-gpg= ）。暗号化された =~/.authinfo.gpg= を先頭に置く
- EasyPG によるファイル暗号化サポート（ =auth-core= ）
- =pass= ベースの資格情報参照（ =auth-core= 。 =pass= が実行ファイルとして存在するときだけ有効）
- 環境変数の検証（ =auth-core= 。確かめるのは =GPG_KEY_ID= だけで、無ければ警告する）
- 診断コマンド（ =my/auth-gpg-verify= 、 =my/auth-gpg-init-template= 、 =my/auth-keychain-verify= ）

auth も ui 層に依存してはいけません。

*Keychain バックエンドの扱い*

macOS では Keychain バックエンド（ =auth-keychain= ）を、 =personal/device-darwin.el= が有効化します
（=auth-keychain-enable= 自体の既定値は =nil= ）。macOS 以外では、このモジュールは何もしません。無効にしたい場合は、モジュールのロード前に personal 層で
=auth-keychain-enable= を上書きしてください。

*** orgx

Org Mode の拡張群です。orgx の全モジュールは =core= 、 =ui= 、 =auth= 、 =completion= のみに
依存し、 =vcs= や =dev= には依存しません。

本層は 14 モジュールで構成されます。 =my:modules= に含まれる正規モジュールは 10 です。
残る 4 つ（ =orgx-typography= 、 =orgx-brain= 、 =orgx-roam-ui= 、 =orgx-citar= ）はオプション
拡張です。このうち =orgx-typography= 、 =orgx-brain= 、 =orgx-citar= は =personal/user.el= が
=my:modules-extra= に宣言します。 =orgx-roam-ui= は tangle されますが、既定では
=my:modules-extra= に含めません（Org を起動時に引き込まないため。理由は当該モジュールと
=personal/user.el= を参照）。

モジュール別の責務:

- =orgx-core= — Org のディレクトリ構成、 =defvar= によるパス変数、アジェンダの
  フォールバック（フェーズ 1: =inbox.org= ）、TODO キーワード、refile ターゲット、
  キャプチャテンプレート（todo / note / journal / meeting。ブログ記事のテンプレートは =orgx-hugo= が追加する）、
  アーカイブ先、 =after-init-hook= によるアジェンダ再構築（フェーズ 2）
- =orgx-agenda= — キャッシュ付き再帰スキャンによる =org-agenda-files= の生成（ =orgx-core= が after-init で呼ぶ）
- =orgx-extensions= — =org-journal= （journal ディレクトリ）、 =org-roam= （DB の

*orgx がやらないこと*

なってしまいます。

*** personal

ユーザー固有のカスタマイズです。

- 任意（無くてもシステムは動きます）
- 依存の向きでは最上位です。ただし =user.el= と =<ユーザー名>.el= は =modules.el= より前に読み込まれ、変数の上書きと =my:modules-extra= への追加を行います
- 下位層の関数やモジュールは書き換えません（上書きしてよいのは =defvar= / =defcustom= の値だけです）
- 利用者固有の機能（ =personal-llm= のコマンド、 =personal-messages= の定期実行、 =device-wsl= のクリップボード連携など）は、

** Module Structure
:PROPERTIES:
:CUSTOM_ID: module-structure
:END:

どのモジュールも、同じ形をしています。

#+begin_example
;;; module-name.el --- description -*- lexical-binding: t; -*-

;;; Commentary:

責務の説明。

;;; Code:

(require ...)

(defgroup ...)

(defcustom ...)

(defun ...)

(provide 'module-name)

;;; module-name.el ends here
#+end_example

そのうえで、各モジュールは次の 4 つを満たす必要があります。

- *決定論的* — 同じ入力から同じ出力が得られる
- *冪等* — 繰り返し評価しても副作用が重複しない
- *バイトコンパイル下で安全*
- *デーモンモード下で安全*

*** Autoload-Only Modules
:PROPERTIES:
:CUSTOM_ID: autoload-only-modules
:END:

tangle 対象でありながら、意図的に =my:modules= に載せていないモジュールがあります。これらは
調整役のモジュールに書かれた =autoload= 宣言によって、必要になったときだけロードされます。

起動時に無条件でロードしては困る場合 — たとえば LSP バックエンドの選択や、オプションの UI
バンドル — がこれに当たります。使わない方のバックエンドまで読み込んでしまっては、
切り替え可能である意味がありません。

| モジュール          | 宣言元          | 起動条件                                |
|---------------------+-----------------+-----------------------------------------|
| =dev-lsp-eglot=     | =dev-lsp-bridge= | after-init 時、 =my:use-lsp= が =eglot= のとき |
| =dev-lsp-mode=      | =dev-lsp-bridge= | after-init 時、 =my:use-lsp= が =lsp= のとき |
| =ui-doom-modeline=  | =ui-bundles= | after-init 時、 =my:use-ui= が =doom= のとき |
| =ui-nano-modeline=  | =ui-bundles= | after-init 時、 =my:use-ui= が =nano= のとき |
| =ui-doom-nano-modeline= | =ui-bundles= | after-init 時、 =my:use-ui= が =doom-nano= のとき |
| =ui-nano-palette=   | =ui-theme=      | =my:use-ui= が =nano= / =doom-nano= のとき =(require 'ui-nano-palette nil t)= |
| =ui-nano-modeline-items= | =ui-nano-modeline= | =ui-nano-modeline= のロード時に =(require 'ui-nano-modeline-items)= |

これらのモジュールは、 =leaf= 宣言で =:require t= を使ってはいけません。 =autoload= エントリが
load-path 上の可用性を保証してくれるので、そこで =:require t= を書くと、遅延ロードの意味が
無くなってしまいます。

*** Optional Extra Modules

=my:modules= に載っていないモジュールには、もう一つ別の系統があります。 =my:modules-extra=
です。

autoload との違いは、遅延しない点にあります。ローダは =(append my:modules my:modules-extra)=
として両者を連結するので、extra のモジュールも通常のシーケンスの中で require されます。
つまりこれは「遅延ロード」ではなく「オプトイン」の仕組みです。

=personal/user.el= が宣言しているのは次の 5 つです。macOS では、これに加えて =personal/device-darwin.el= が =dev-apple-music= を足します。

| モジュール        | 層    | 目的 |
|-------------------+-------+------|
| =ui-visual-aids=  | ui    | pulsar、hl-todo、rainbow-delimiters、indent-bars |
| =ui-macos=        | ui    | macOS のタイトルバー、タスクバー、コンパイル中のスリープ抑止 |
| =orgx-typography= | orgx  | valign、org-appear |
| =orgx-brain=      | orgx  | org-brain マインドマップビュー |
| =orgx-citar=      | orgx  | citar + org-cite による文献引用管理 |
| =dev-apple-music= | dev   | osascript による Apple Music の操作（macOS のみ。 =personal/device-darwin.el= が加える） |

=orgx-roam-ui= は上の表に含まれません。意図的に =my:modules-extra= から外しています。
このモジュールを有効にすると org-roam-ui がモジュールのロード時に依存を導入し、
=org-roam= → =org= を起動直後に引き込むため、Org の遅延ロードが崩れます。グラフビジュアライザを
常用する場合のみ、 =personal/user.el= の =my:modules-extra= に =orgx-roam-ui= を戻してください。

*なぜ personal 層に置くのか*

これらを =my:modules= ではなく personal 層に置いているのは、表示系や知識グラフ系のツールを
使うかどうかが、共有すべきポリシーではなく個人の好みだからです。そして何より、 =core/= の
モジュールが =ui/= や =orgx/= の feature をロードリストに注入することは、層の原則に真っ向から
反します。

** Package Management
:PROPERTIES:
:CUSTOM_ID: packages
:END:

パッケージはすべて =leaf= マクロで宣言します。

#+begin_example
(leaf vertico
  :straight t
  :custom
  ((vertico-count . 15)))
#+end_example

キーワードの順序は固定です（コーディング規則 4）。順序を守るのは好みの問題ではなく、

** Tangle
:PROPERTIES:
:CUSTOM_ID: tangling
:END:

Org Babel が Emacs Lisp ブロックを展開し、モジュールファイルとして書き出します。

- 各モジュールは =lisp/<layer>/<module>.el= に tangle されます（正本は =org/<layer>.org= ）
- =README.org= と =org/*.org= は、すべて tangle します（ =make tangle= がまとめて行います）
- ディレクトリは自動で作られます（ =:mkdirp yes= ）

実行方法は次のとおりです。

#+begin_example
1. EMACS=/Applications/Emacs.app/Contents/MacOS/Emacs make -C ~/.emacs.d/ reload   # clean + tangle
2. Emacs を再起動する
#+end_example

*初回ブートストラップ（Makefile が無い場合）*

=Makefile= も =scripts/reload.py= も =early-init.el= / =init.el= / =lisp/= も、すべて
この README.org と =org/*.org= からの tangle 生成物で、 =.gitignore= 対象です。 =git clone= 直後は
どれも存在しません。 =make reload= はおろか、 =python3 scripts/reload.py= すらまだ使えない
「鶏と卵」の状態です。

この状態から抜け出せる、依存ゼロの入口が 1 つあります。組み込み Org だけで完結する、
生の Emacs バッチコマンドです。外部パッケージは要りません。straight や leaf の
ブートストラップより前の段階なので、それらにも依存しません。

#+begin_example
emacs -Q --batch --eval '(require (quote ob-tangle))' \
                  --eval '(dolist (f (append (list "README.org") (directory-files "org" t "[.]org$"))) (org-babel-tangle-file f))'
#+end_example

これを一度実行すれば、 =Makefile= ・ =scripts/reload.py= ・ =lisp/*= 一式が生成されます。 =README.org= だけでは =lisp/= は生成されません。正本が複数の Org 文書に分かれているためです。
以後は通常どおり、 =make reload= （またはこのコマンド単体の再実行）で回せます。

なぜ =tangle= ではなく =reload= を使うのか

=reload= ターゲットは、再 tangle の前に =*.elc= を消してくれます。これが無いと、古い
バイトコンパイル済みモジュールが新しい =.el= を覆い隠したまま動き続け、「ソースには存在しない
はずの警告が出る」という厄介な状態に陥ります。原因の切り分けに時間を溶かしがちなので、
基本的には =reload= を使うのが安全です。

*設定の新旧を行き来したとき*

=tangle= は、書き出すファイルを上書きするだけです。tangle 先でなくなったファイルは消しません。ブランチを切り替えたり、
モジュールを統合・改名したコミットを取り込んだりすると、古い =.el= が =lisp/= に残ります。

そこで、 =reload= の最後の段（ =clean-orphans= ）が、どの Org 文書も tangle しない生成物を削除します。
対象は =lisp/= 、 =personal/= 、 =scripts/= の =.el= 、 =.elc= 、 =.py= 、 =.sh= です。
削除せずに一覧だけ見たいときは、 =make check-orphans= を使います（ =make lint= にも含まれます）。

初回セットアップ（上の =emacs -Q --batch= による tangle のあと）は、 =make reload= を 1 回実行すれば足ります。
その tangle で最新の =Makefile= がすでにできているので、 =reload= の途中で =Makefile= が書き換わることはありません。2 回目は不要です。

2 回目が要るのは、 =git pull= などで =Makefile= の内容が変わる更新を取り込んだときだけです。
=reload= の途中で =Makefile= 自身が書き換わった場合は、新しい =Makefile= でもう一度 =reload= を実行します（自動で再実行されます）。

ただし、取り込む前から手元にある古い =Makefile= には、この仕組みがありません。そのため、 *取り込んだ直後の 1 回目の =make reload= は
=Makefile= を更新するだけ* で終わることがあります。 =[reload]= の表示が =Makefile= の更新だけだったら、もう一度
=make reload= を実行してください。

** Design Principles
:PROPERTIES:
:CUSTOM_ID: design-tenets
:END:

*** Deterministic Behaviour

起動は毎回同じ結果を生まなければなりません。 =my:modules= のリストが、ロード順に関する唯一の
正です。ディレクトリを走査して見つけたものを順不同で読む、といったことはしません。

*** Explicit Dependencies

モジュールは依存関係を明示的に =require= します。暗黙の自動探索は行いません。

*** Layer Ownership

各層は自分の領域だけを所有し、他の層を書き換えません。

*** Delete Safety

モジュールを 1 つ削除しても、システムが壊れてはいけません。これを実際に保証しているのが、
ローダの =condition-case= によるエラー隔離です。あるモジュールの読み込みが失敗しても、
そこで起動が止まることはなく、残りは読み込まれます。失われるのは利便性だけで、正しさは
保たれる、という状態を目指しています。

*** Forward Compatibility

*** Startup Performance

シェル環境変数の取り込みは、必要最小限の変数に絞っています。

*何が遅いのか*

macOS では =exec-path-from-shell= がログインシェルを起動して =exec-path= とプロセス環境を
組み立てます。このシェル起動そのものに、およそ 200〜500 ms かかります。設定全体の起動時間に
対して、これは無視できない比率です。

*どう抑えているか*

1. =exec-path-from-shell-arguments= を ='("-l")= （ログインシェルのみ、対話フラグなし）に
   しています。既定の ='("-l" "-i")= と比べ、対話シェルの起動ファイル読み込みを省けるぶん、
   起動時間はおよそ半分になります。

2. =exec-path-from-shell-variables= を =("PATH" "LANG")= だけに絞っています。API キー
   （ =OPENAI_API_KEY= 、 =OPENROUTER_API_KEY= ）は、 =utils-claude.el= の中で必要になった時点で
   =auth-source= 経由で =~/.authinfo.gpg= から取得します。

2 番目が効くのは、これらのキーを export しているログインプロファイルを読み込む理由が、
そもそも無くなるからです。結果として =exec-path-from-shell= のコストは、最小構成のログイン
シェルを起動するという、削りようのない部分だけになります。

各層が明確な責務を持つことで、挙動が予測しやすくなり、UI を差し替えられるようになり、個人

#+begin_src makefile :tangle Makefile :mkdirp no :padline no
  # Makefile — モジュール式 Emacs 設定のためのワンパス・ビルダー
  # - 既定 / `make all` : onepass-init（tangle -> 差分バイトコンパイル）
  # - `make onepass-q`  : -Q（最小環境）で tangle -> 全バイトコンパイル
  # - パスはリポジトリルートから絶対化する（"lisp/personal" の混同を防ぐため）

  SHELL := /bin/sh


  # ---- リポジトリルートと絶対化したディレクトリ -----------------------------------
  ROOT := $(CURDIR)

  EMACS  ?= emacs
  ORG    ?= README.org
  EARLY  ?= early-init.el
  INIT   ?= init.el
  RSVG_CONVERT ?= rsvg-convert
  DOT    ?= dot
  MMDC   ?= mmdc
  # mmdc が同梱の Chrome を解決できない環境向け。puppeteer 用の JSON 設定ファイルへの
  # パスを渡すと `mmdc -p $(PUPPETEER_CONFIG)` として使われる。空なら渡さない。
  #   例: {"executablePath": "/path/to/chrome", "args": ["--no-sandbox"]}
  # リポジトリ直下に puppeteer-config.json があれば自動採用する（$(wildcard ...) は
  # ファイルが無ければ空文字になるので、無い環境では今まで通り渡さずフォールバックする）。
  # コマンドラインで PUPPETEER_CONFIG=... を指定すれば ?= なのでいつでも上書きできる。
  PUPPETEER_CONFIG ?= $(wildcard puppeteer-config.json)

  # これらは常にリポジトリルート直下として扱う
  LISPDIR_REL     ?= lisp
  PERSONALDIR_REL ?= personal
  SVGDIR_REL      ?= svg

  LISPDIR     := $(abspath $(ROOT)/$(LISPDIR_REL))
  PERSONALDIR := $(abspath $(ROOT)/$(PERSONALDIR_REL))
  SVGDIR      := $(abspath $(ROOT)/$(SVGDIR_REL))
  ORG := $(abspath $(ROOT)/$(ORG))
  # 層別の Org 文書と補助スクリプト（org/*.org。tools.org を含む）。README.org とあわせてすべて tangle・検査する。
  LAYER_ORGS := $(sort $(wildcard $(ROOT)/org/*.org))
  EXTRA_ORGS := $(wildcard $(ROOT)/tools.org) $(LAYER_ORGS)
  ALL_ORGS   := $(ORG) $(EXTRA_ORGS)
  EARLY := $(abspath $(ROOT)/$(EARLY))
  INIT  := $(abspath $(ROOT)/$(INIT))

  STRICT_BYTE_WARN ?= 0   # Treat byte-compile warnings as errors
  NATIVE_COMPILE   ?= 1   # Prefer native-compile if available

  # ---- Emacs の実行方法と共通の eval スニペット -----------------------------------
  EMACS_BATCH := "$(EMACS)" --batch
  EMACS_Q     := $(EMACS_BATCH) -Q

  EVAL_STRICT := $(if $(filter 1,$(STRICT_BYTE_WARN)),--eval "(setq byte-compile-error-on-warn t)",)
  EVAL_NATIVE := $(if $(filter 1,$(NATIVE_COMPILE)),--eval "(setq comp-deferred-compilation t)",)

  # org-babel-tangle は既定で各ソースブロックの「共通の先頭空白」を列（column）単位で
  # 計算して取り除く。この計算はタブをいったんスペースへ展開してから行うため、この
  # ブロックの recipe 行（先頭がタブ 1 文字）はタブが tab-width 分のスペース列へ展開
  # されたうえで共通分だけが差し引かれ、結果として recipe 行の先頭がタブではなく
  # 半端なスペース列に化けてしまう（Make が "missing separator" で落ちる原因）。
  # org-src-preserve-indentation を非 nil にして、この先頭空白の除去処理自体を
  # 無効化し、ソースに書かれたタブをタブのまま出力させる。
  #
  # 注意: .RECIPEPREFIX（GNU Make 3.82+ の機能）で recipe 先頭マーカーをタブ以外の
  # 文字に変える案も検討したが、macOS 標準の /usr/bin/make は GPLv3 回避のため
  # 3.81 に固定されており .RECIPEPREFIX を認識しない。タブそのものを使う今の方式は
  # Make のバージョンに依存しない。
  EVAL_PRESERVE_INDENT := --eval "(setq org-src-preserve-indentation t)"

  # ---- 既定ターゲット（引数なし）--------------------------------------------------
  .PHONY: all onepass-init onepass-q clean distclean distclean-deps show-files echo-paths tangle reload check-cookies check-tangle check-emphasis figures clean-figures dot-tangle dot-svg mmd-tangle mmd-svg diagrams clean-diagrams help
  all: onepass-init

  # ---- ワンパス（early+init 環境）: tangle -> 差分コンパイル -----------------------
  onepass-init: $(ORG)
	@echo "[onepass-init] tangle -> incremental byte-compile (init loaded)"
	@$(EMACS_BATCH) -l "$(EARLY)" -l "$(INIT)" \
  	  $(EVAL_STRICT) $(EVAL_NATIVE) \
  	  --eval "(setq org-confirm-babel-evaluate nil)" \
  	  --eval "(require 'org)" \
  	  --eval "(org-babel-tangle-file \"$(ORG)\")" \
  	  $(foreach f,$(EXTRA_ORGS),--eval "(org-babel-tangle-file \"$(f)\")") \
  	  --eval "(let ((org-src-preserve-indentation t)) (org-babel-tangle-file \"$(ORG)\" nil \"makefile\"))" \
  	  --eval "(let* ((dirs (delq nil (list (and (file-directory-p \"$(LISPDIR)\") \"$(LISPDIR)\") \
  	                                        (and (file-directory-p \"$(PERSONALDIR)\") \"$(PERSONALDIR)\"))))) \
  	            (dolist (d dirs) (byte-recompile-directory d 0)) \
  	            (when (and (featurep 'comp) (bound-and-true-p comp-deferred-compilation)) \
  	              (dolist (d dirs) (ignore-errors (native-compile-async d 'recursively)))))" \
  	  --eval "(message \"[onepass-init] done\")"

  # ---- onepass-q 専用: -Q 実行時の leaf の任意注入 --------------------------------
  # -Q（init.el を読まない最小環境）は straight 経由でインストールした leaf /
  # leaf-keywords を自動では load-path に乗せない。onepass-q はこれを手動で
  # 注入するため、ここで STRAIGHT_BASE_DIR / LEAF_DIR / LEAFKW_DIR / EVAL_LEAF
  # を解決する。
  #
  # スコープの注記: この一連の変数を参照するのは onepass-q・echo-paths・
  # distclean-deps だけである。reload（= clean tangle check-cookies）・
  # tangle 単体・clean はいずれも参照しない。STRAIGHT_BASE_DIR /
  # MY_D_CACHE_DIR は再帰展開変数（?=）なので、$(shell ...) はどこかの
  # ターゲットが実際にこの変数を参照したときにのみ評価される — 参照されなければ、
  # straight や leaf が未インストールの環境で `make reload` 等を実行しても
  # この行が原因で失敗することはない。
  #
  # 注意（$XDG_CACHE_HOME）: early-init.el の my:d:cache は
  # `$XDG_CACHE_HOME/emacs/`（未設定時は `$HOME/.cache/emacs/`）に解決され、
  # straight-base-dir にはこの my:d:cache がそのまま渡る（straight.el 自身が
  # その配下に `straight/` を作る）。以前はここで straight-base-dir の値を
  # そのまま「straight ディレクトリそのもの」として使っており、`straight/`
  # の一段が欠落していた（LEAF_DIR / LEAFKW_DIR が実際には存在しないパスを
  # 指し、onepass-q の leaf 注入が静かに失敗する不具合があった）。また未束縛時
  # フォールバックも $XDG_CACHE_HOME を無視して $HOME/.emacs.d/straight に
  # 固定されていた。両方とも my:d:cache の定義（early-init.el 3) 基本ディレクトリ
  # 参照）に合わせて修正済み。
  STRAIGHT_BASE_DIR ?= $(shell \
    if [ -f "$(EARLY)" ]; then \
      $(EMACS_Q) -l "$(EARLY)" \
        --eval "(princ (expand-file-name \"straight\" \
                         (if (boundp 'straight-base-dir) straight-base-dir user-emacs-directory)))"; \
    else \
      printf "%s" "$${XDG_CACHE_HOME:-$$HOME/.cache}/emacs/straight"; \
    fi)
  LEAF_DIR   := $(STRAIGHT_BASE_DIR)/repos/leaf.el
  LEAFKW_DIR := $(STRAIGHT_BASE_DIR)/repos/leaf-keywords.el

  # MY_D_CACHE_DIR : early-init.el の my:d:cache（straight-base-dir の親であり、
  # eln-cache や一部パッケージ（dirvish 等）のキャッシュも同居する、この設定専用の
  # XDG キャッシュルート）。distclean-deps が実キャッシュ全体を一括削除するために
  # 使う。STRAIGHT_BASE_DIR から逆算せず、my:d:cache を直接問い合わせる（両者の
  # 親子関係という前提に依存しないため）。
  MY_D_CACHE_DIR ?= $(shell \
    if [ -f "$(EARLY)" ]; then \
      $(EMACS_Q) -l "$(EARLY)" \
        --eval "(princ (if (boundp 'my:d:cache) my:d:cache \
                          (expand-file-name \"emacs\" \
                            (or (getenv \"XDG_CACHE_HOME\") \
                                (expand-file-name \".cache\" (getenv \"HOME\"))))))"; \
    else \
      printf "%s" "$${XDG_CACHE_HOME:-$$HOME/.cache}/emacs"; \
    fi)

  EVAL_LEAF := \
    --eval "(let* ((ldir \"$(LEAF_DIR)\") (kwdir \"$(LEAFKW_DIR)\")) \
              (when (file-directory-p ldir)  (add-to-list 'load-path ldir)) \
              (when (file-directory-p kwdir) (add-to-list 'load-path kwdir)) \
              (ignore-errors (require 'leaf)) \
              (ignore-errors (require 'leaf-keywords)) \
              (when (featurep 'leaf-keywords) (leaf-keywords-init)))"

  # ---- ワンパス（-Q 最小環境）: tangle -> 全コンパイル -----------------------------
  onepass-q: $(ORG)
	@echo "[onepass-q] -Q tangle -> full byte-compile (init not loaded)"
	@$(EMACS_Q) \
  	  $(EVAL_LEAF) $(EVAL_STRICT) $(EVAL_NATIVE) \
  	  --eval "(setq org-confirm-babel-evaluate nil)" \
  	  --eval "(require 'org)" \
  	  --eval "(org-babel-tangle-file \"$(ORG)\")" \
  	  $(foreach f,$(EXTRA_ORGS),--eval "(org-babel-tangle-file \"$(f)\")") \
  	  --eval "(let ((org-src-preserve-indentation t)) (org-babel-tangle-file \"$(ORG)\" nil \"makefile\"))" \
  	  --eval "(let* ((dirs (delq nil (list (and (file-directory-p \"$(LISPDIR)\") \"$(LISPDIR)\") \
  	                                        (and (file-directory-p \"$(PERSONALDIR)\") \"$(PERSONALDIR)\"))))) \
  	            (dolist (d dirs) (byte-recompile-directory d t)) \
  	            (when (and (featurep 'comp) (bound-and-true-p comp-deferred-compilation)) \
  	              (dolist (d dirs) (ignore-errors (native-compile-async d 'recursively)))))" \
  	  --eval "(message \"[onepass-q] done\")"

  # ---- ユーティリティ -------------------------------------------------------------
  show-files:
	@echo "[list] $(LISPDIR)";    { [ -d "$(LISPDIR)" ] && find "$(LISPDIR)" -type f -name '*.el' | sort; } || true
	@echo "[list] $(PERSONALDIR)"; { [ -d "$(PERSONALDIR)" ] && find "$(PERSONALDIR)" -type f -name '*.el' | sort; } || true

  echo-paths:
	@echo "ROOT=$(ROOT)"; \
  	echo "EARLY=$(EARLY)"; \
  	echo "INIT=$(INIT)"; \
  	echo "LISPDIR=$(LISPDIR)"; \
  	echo "PERSONALDIR=$(PERSONALDIR)"; \
  	echo "SVGDIR=$(SVGDIR)"; \
  	echo "STRAIGHT_BASE_DIR=$(STRAIGHT_BASE_DIR)"; \
  	echo "LEAF_DIR=$(LEAF_DIR)"; \
  	echo "LEAFKW_DIR=$(LEAFKW_DIR)"; \
  	echo "MY_D_CACHE_DIR=$(MY_D_CACHE_DIR)"

  clean:
	@echo "[clean] remove *.elc under $(LISPDIR) and $(PERSONALDIR)"
	@{ [ -d "$(LISPDIR)" ] && find "$(LISPDIR)" -type f -name '*.elc' -delete; } 2>/dev/null || true
	@{ [ -d "$(PERSONALDIR)" ] && find "$(PERSONALDIR)" -type f -name '*.elc' -delete; } 2>/dev/null || true

  # distclean は README.org からの tangle 生成物一式を削除し、fresh clone 相当に戻す。
  # 対象は早期に消えても実害のない「ソースから常に再生成できるもの」だけ（early-init.el
  # / init.el / lisp/ / personal/ / scripts/ / LICENSE / Makefile 自身、および svg/ 配下の
  # *.dot / *.mmd / *.pdf 中間生成物）。svg/*.svg は git 管理下の成果物なので対象外。
  # ChangeLog も README.org の Changelog 節から tangle される生成物（GNU 形式）で、
  # 常に再生成できるため distclean の対象。
  # straight/ の package clone や eln-cache 等の依存物・実行時キャッシュは distclean には
  # 含めない（再取得・再コンパイルに数分〜かかり、distclean を打つたびに発生させたくない
  # ため）。それらを消したい場合は distclean-deps を使う。
  #
  # 注意: Makefile 自身も削除されるため、実行後は make が一切使えなくなる。再び使うには
  # Tangle 節の「初回ブートストラップ」コマンド（emacs -Q --batch tangle）が必要。
  distclean: clean
	@echo "[distclean] remove stray *.eln"
	@find "$(ROOT)" -type f -name '*.eln' -delete
	@echo "[distclean] remove tangle-generated files (early-init.el init.el lisp/ personal/ scripts/ LICENSE svg intermediates)"
	@rm -f "$(EARLY)" "$(INIT)" "$(ROOT)/LICENSE"
	@rm -rf "$(LISPDIR)" "$(PERSONALDIR)" "$(ROOT)/scripts"
	@{ [ -d "$(SVGDIR)" ] && find "$(SVGDIR)" \( -name '*.dot' -o -name '*.mmd' -o -name '*.pdf' \) -delete; } 2>/dev/null || true
	@echo "[distclean] remove ChangeLog (tangled from README.org Changelog section)"
	@rm -f "$(ROOT)/ChangeLog"
	@echo "[distclean] remove Makefile (re-bootstrap: see README.org Tangle section)"
	@rm -f "$(ROOT)/Makefile"

  # distclean-deps は distclean よりさらに踏み込んだ、破壊的な操作。straight/ のパッケージ
  # clone・ネイティブコンパイルキャッシュ・no-littering の実行時状態を削除する。再取得や
  # 再コンパイルに数分〜十数分かかりうるため distclean には含めず、独立したターゲットに
  # している。
  #
  # 実キャッシュ（straight/ の package clone・eln-cache）は $XDG_CACHE_HOME/emacs/
  # （未設定時は $HOME/.cache/emacs/）配下にあり、$(ROOT) の外なので $(MY_D_CACHE_DIR)
  # を使って削除する（$(ROOT)/straight や $(ROOT)/.cache ではない — 以前はここが
  # 誤っており、$XDG_CACHE_HOME を考慮していなかった）。$(ROOT)/eln-cache は
  # dot-tangle 等の `-Q` バッチ実行が early-init.el を経由せず作る別物の副産物
  # （$HOME/.emacs.d が本リポジトリへのシンボリックリンクであるため、-Q の既定
  # user-emacs-directory がここを指す）なので、これも別途削除する。$(ROOT)/.etc /
  # $(ROOT)/.var（no-littering-etc-directory / -var-directory）はリポジトリ直下
  # のままなので従来どおり。
  distclean-deps:
	@echo "[distclean-deps] remove $(MY_D_CACHE_DIR) (straight/ + eln-cache/ + other per-package caches under XDG_CACHE_HOME)"
	@rm -rf "$(MY_D_CACHE_DIR)"
	@echo "[distclean-deps] remove stray $(ROOT)/eln-cache (from -Q batch runs; ~/.emacs.d symlinks here) and $(ROOT)/.etc $(ROOT)/.var"
	@rm -rf "$(ROOT)/eln-cache" "$(ROOT)/.etc" "$(ROOT)/.var"

  # ---- dot-tangle : README.org の dot ソースブロックを svg/*.dot として書き出す ---------
  # Appendix の :header-args:dot: :tangle svg/*.dot に従い、org-babel-tangle-file の
  # LANG 引数に "dot" を渡して dot 言語のブロックだけを対象に書き出す。design_spec.org は
  # 廃止済み（内容は README.org の Modular Loader & Core Suite 内の各モジュール節、および
  # Appendix に統合された）ため、対象は $(ORG) のみでよい。
  dot-tangle: $(ORG)
	@echo "[dot-tangle] $(ORG) -> $(SVGDIR)/*.dot"
	@$(EMACS_Q) \
     --eval "(require 'org)" \
     --eval "(require 'ob-core)" \
     --eval "(setq org-confirm-babel-evaluate nil noninteractive t)" \
     --eval "(org-babel-tangle-file \"$(ORG)\" nil \"dot\")"

  # ---- dot-svg : svg/*.dot を dot -Tsvg で同名の svg/*.svg へレンダリングする -----------
  # figures と同じ差分ルール（*.dot が対応する *.svg より新しい、または *.svg が無い場合の
  # み再生成）。dot コマンドが無ければ、その場でインストール手順を案内して失敗する。
  # 日本語ラベルを含む図は、fontconfig で解決できる CJK 対応フォント
  # （例: Noto Sans CJK JP）が dot ソース側の fontname に指定されている前提。
  dot-svg: dot-tangle
	@command -v "$(DOT)" >/dev/null 2>&1 || { \
     echo "[dot-svg] $(DOT) not found. Install with: brew install graphviz (or apt-get install graphviz)"; \
     exit 1; \
   }
	@if [ ! -d "$(SVGDIR)" ]; then \
     echo "[dot-svg] $(SVGDIR) not found; nothing to do"; \
     exit 0; \
   fi
	@echo "[dot-svg] rendering *.dot -> *.svg under $(SVGDIR) ..."
	@count=0; \
   for f in $$(find "$(SVGDIR)" -name '*.dot' | sort); do \
     svg="$${f%.dot}.svg"; \
     if [ ! -f "$$svg" ] || [ "$$f" -nt "$$svg" ]; then \
       echo "  $$f -> $$svg"; \
       "$(DOT)" -Tsvg "$$f" -o "$$svg" || exit 1; \
       count=$$((count + 1)); \
     fi; \
   done; \
   echo "[dot-svg] done ($$count rendered)"

  # ---- mmd-tangle : README.org の mermaid ソースブロックを svg/*.mmd として書き出す ------
  # :header-args:mermaid: :tangle svg/*.mmd に従い、LANG 引数に "mermaid" を渡して
  # tangle する。mermaid ブロックを持つのは README.org（tangle-flow.mmd）のみ。
  mmd-tangle: $(ORG)
	@echo "[mmd-tangle] $(ORG) -> $(SVGDIR)/*.mmd"
	@$(EMACS_Q) \
     --eval "(require 'org)" \
     --eval "(require 'ob-core)" \
     --eval "(setq org-confirm-babel-evaluate nil noninteractive t)" \
     --eval "(org-babel-tangle-file \"$(ORG)\" nil \"mermaid\")"

  # ---- mmd-svg : svg/*.mmd を mmdc で同名の svg/*.svg へレンダリングする ----------------
  # mmdc（@mermaid-js/mermaid-cli）は内部で Puppeteer 経由の Chrome を必要とする。
  # mmdc が同梱する puppeteer-core は特定バージョンの Chrome に固定されているため、
  # `npx puppeteer browsers install chrome`（や chrome-headless-shell）で入れた
  # 別バージョンでは一致せず、依然として "Could not find Chrome" で失敗することを実機で
  # 確認済み。確実なのは PUPPETEER_CONFIG に executablePath を明示すること —
  # バージョン不一致があっても executablePath を直接指定すれば通ることを確認済み。
  # （例: make mmd-svg PUPPETEER_CONFIG=puppeteer-config.json）。
  mmd-svg: mmd-tangle
	@command -v "$(MMDC)" >/dev/null 2>&1 || { \
     echo "[mmd-svg] $(MMDC) not found. Install with: npm install -g @mermaid-js/mermaid-cli"; \
     exit 1; \
   }
	@if [ ! -d "$(SVGDIR)" ]; then \
     echo "[mmd-svg] $(SVGDIR) not found; nothing to do"; \
     exit 0; \
   fi
	@echo "[mmd-svg] rendering *.mmd -> *.svg under $(SVGDIR) ..."
	@count=0; \
   for f in $$(find "$(SVGDIR)" -name '*.mmd' | sort); do \
     svg="$${f%.mmd}.svg"; \
     if [ ! -f "$$svg" ] || [ "$$f" -nt "$$svg" ]; then \
       echo "  $$f -> $$svg"; \
       if [ -n "$(PUPPETEER_CONFIG)" ]; then \
         "$(MMDC)" -i "$$f" -o "$$svg" -b white -p "$(PUPPETEER_CONFIG)" || { \
           echo "[mmd-svg] mmdc failed even with PUPPETEER_CONFIG=$(PUPPETEER_CONFIG)."; \
           echo "[mmd-svg] Check that the executablePath inside it actually exists."; \
           exit 1; \
         }; \
       else \
         "$(MMDC)" -i "$$f" -o "$$svg" -b white || { \
           echo "[mmd-svg] mmdc failed. mmdc's bundled puppeteer-core is pinned to a"; \
           echo "[mmd-svg] specific Chrome build, so \"npx puppeteer browsers install\""; \
           echo "[mmd-svg] usually fetches a DIFFERENT version and still fails to match."; \
           echo "[mmd-svg] The reliable fix is to point PUPPETEER_CONFIG at any Chrome/"; \
           echo "[mmd-svg] Chromium binary you already have (version mismatch is fine"; \
           echo "[mmd-svg] once executablePath is set explicitly):"; \
           echo "[mmd-svg]   {\"executablePath\": \"/path/to/chrome\", \"args\": [\"--no-sandbox\"]}"; \
           echo "[mmd-svg]   make mmd-svg PUPPETEER_CONFIG=puppeteer-config.json"; \
           exit 1; \
         }; \
       fi; \
       count=$$((count + 1)); \
     fi; \
   done; \
   echo "[mmd-svg] done ($$count rendered)"

  # ---- diagrams : dot-svg + mmd-svg をまとめて実行するショートハンド --------------------
  diagrams: dot-svg mmd-svg
	@echo "[diagrams] $(SVGDIR)/*.dot, $(SVGDIR)/*.mmd -> $(SVGDIR)/*.svg up to date"

  # ---- clean-diagrams : diagrams が生成した *.dot / *.mmd / *.svg を削除 ---------------
  # *.dot・*.mmd と同名の *.svg のみを対象とする（$(SVGDIR) 配下に手動で置いた無関係な
  # ファイル、たとえば demo.png や emacs_keybindings_cheatsheet.svg のような tangle 元を
  # 持たない手動アセットを誤って消さないよう、tangle 由来のソースが存在するものだけ削除する）。
  clean-diagrams:
	@echo "[clean-diagrams] remove generated *.dot / *.mmd / *.svg under $(SVGDIR)"
	@if [ -d "$(SVGDIR)" ]; then \
     for f in $$(find "$(SVGDIR)" \( -name '*.dot' -o -name '*.mmd' \) | sort); do \
       svg="$${f%.*}.svg"; \
       [ -f "$$svg" ] && rm -f "$$svg"; \
       rm -f "$$f"; \
     done; \
   fi

  # ---- stage : 追跡対象だけを stage する ------------------------------------------
  # 中止の判定には、削除（--diff-filter=d で除外）を含めない。TRACKED の外にあるファイルの削除は、
  # 以前追跡していたファイルを消した意図の変更である（例: tools.org を org/tools.org へ移したときの、
  # 旧パスの削除）。除外パターンを付けると Git が名前変更の対応を組めず、旧パスが「外のファイルの
  # ステージ」に見えてしまうため、削除は見ない。追加・変更が TRACKED の外にあれば、従来どおり中止する。
  # このリポジトリで git が追跡するのは README.org などの少数のファイルだけで、
  # それ以外（lisp/ personal/ scripts/ Makefile ChangeLog など）は tangle の生成物として
  # .gitignore されている。`git add .` は .gitignore にまだ書いていない新規ファイルまで
  # 拾うため、追跡対象を TRACKED に列挙し、そのパスだけを stage する。
  # ステージ済みのファイルに TRACKED の外のものが混ざっていれば、コミット前に中止する
  # （`:(exclude)` の pathspec を TRACKED から組み立てるので、許可リストは TRACKED の 1 か所）。
  # 追跡するファイルが増えたら TRACKED に足す。
  TRACKED := README.org org AGENTS.md demo.png puppeteer-config.json .gitignore svg

  .PHONY: stage
  stage:
	@git add -A -- $(TRACKED)
	@bad=$$(git diff --cached --name-only --diff-filter=d -- . $(foreach f,$(TRACKED),':(exclude)$(f)')); \
  	if [ -n "$$bad" ]; then \
  	  echo "[stage] TRACKED の外のファイルがステージされています:"; echo "$$bad"; exit 1; \
  	fi
	@git status --short

  # ---- figures : *.svg を rsvg-convert で同名の *.pdf へ事前変換 -------------------
  # 本文書（および他の org 文書）の LaTeX/PDF エクスポートは、SVG を
  # svg パッケージ経由で Inkscape に渡す方式を採用していない（mactex-no-gui 環境に
  # Inkscape が無く、実機で `Inkscape version not detected` により失敗することを
  # 確認済み）。代わりに $(SVGDIR)/*.svg を事前に同名の *.pdf へ変換しておき、
  # orgx-export--svg-to-pdf-graphics（orgx/orgx-export.el 側）が LaTeX エクスポート時に
  # \includegraphics の拡張子を .svg -> .pdf に書き換える運用を前提とする。
  #
  # 差分のみ変換する（*.svg が対応する *.pdf より新しい、または *.pdf が無い場合のみ
  # 変換を実行）。rsvg-convert コマンドが無ければ、その場でインストール手順を
  # 案内して失敗する（CI では未インストールを黙って無視しない）。
  # diagrams（dot/mmd -> svg）を先に実行し、変換元の *.svg が揃っていることを保証してから
  # svg -> pdf の変換に入る。
  #
  # mmdc（Mermaid）が出力する *.svg はラベルをすべて <foreignObject> 内の HTML
  # （<div>/<span>）として埋め込む。librsvg は foreignObject を描画できない
  # （実機で svg/tangle-flow.pdf のラベルが全て空白になることを確認済み）ため、
  # 同名の *.mmd が存在する *.svg（= Mermaid 由来）だけは rsvg-convert を使わず、
  # Puppeteer（実ブラウザエンジン）で HTML を正しく描画できる mmdc 自身に
  # -o *.pdf -f（pdfFit）で直接 PDF を吐かせる。dot（Graphviz）由来の *.svg は
  # ネイティブな <text> 要素だけで構成されるため、従来どおり rsvg-convert で問題ない。
  # mmd-svg と同じ理由で mmdc 側の Chrome 解決に失敗しうるため、$(PUPPETEER_CONFIG)
  # が設定されていれば同様に -p で渡す。
  figures: diagrams
	@command -v "$(RSVG_CONVERT)" >/dev/null 2>&1 || { \
  	  echo "[figures] $(RSVG_CONVERT) not found. Install with: brew install librsvg"; \
  	  exit 1; \
  	}
	@if [ ! -d "$(SVGDIR)" ]; then \
  	  echo "[figures] $(SVGDIR) not found; nothing to do"; \
  	  exit 0; \
  	fi
	@echo "[figures] converting *.svg -> *.pdf under $(SVGDIR) ..."
	@count=0; \
  	 for f in $$(find "$(SVGDIR)" -name '*.svg' | sort); do \
  	   pdf="$${f%.svg}.pdf"; \
  	   mmd="$${f%.svg}.mmd"; \
  	   if [ ! -f "$$pdf" ] || [ "$$f" -nt "$$pdf" ]; then \
  	     if [ -f "$$mmd" ]; then \
  	       command -v "$(MMDC)" >/dev/null 2>&1 || { \
  	         echo "[figures] $(MMDC) not found (needed for Mermaid-sourced $$mmd). Install with: npm install -g @mermaid-js/mermaid-cli"; \
  	         exit 1; \
  	       }; \
  	       echo "  $$mmd -> $$pdf (via mmdc, foreignObject-safe)"; \
  	       if [ -n "$(PUPPETEER_CONFIG)" ]; then \
  	         "$(MMDC)" -i "$$mmd" -o "$$pdf" -f -p "$(PUPPETEER_CONFIG)" || exit 1; \
  	       else \
  	         "$(MMDC)" -i "$$mmd" -o "$$pdf" -f || exit 1; \
  	       fi; \
  	     else \
  	       echo "  $$f -> $$pdf"; \
  	       "$(RSVG_CONVERT)" -f pdf -o "$$pdf" "$$f" || exit 1; \
  	     fi; \
  	     count=$$((count + 1)); \
  	   fi; \
  	 done; \
  	 echo "[figures] done ($$count converted)"

  # ---- clean-figures : figures が生成した *.pdf を削除 ------------------------------
  # *.svg と同名の *.pdf のみを対象とする（$(SVGDIR) 配下に手動で置いた無関係な
  # *.pdf を誤って消さないよう、対応する *.svg が存在するものだけ削除する）。
  clean-figures:
	@echo "[clean-figures] remove generated *.pdf under $(SVGDIR)"
	@if [ -d "$(SVGDIR)" ]; then \
  	  for f in $$(find "$(SVGDIR)" -name '*.svg' | sort); do \
  	    pdf="$${f%.svg}.pdf"; \
  	    if [ -f "$$pdf" ]; then rm -f "$$pdf"; fi; \
  	  done; \
  	fi

  tangle:
	@echo "[tangle] $(ALL_ORGS)"
	@$(EMACS_Q) \
  	  --eval "(require 'org)" \
  	  --eval "(require 'ob-core)" \
  	  --eval "(org-babel-do-load-languages 'org-babel-load-languages '((emacs-lisp . t)))" \
  	  --eval "(setq org-confirm-babel-evaluate nil noninteractive t)" \
  	  --eval "(org-babel-tangle-file \"$(ORG)\")" \
  	  $(foreach f,$(EXTRA_ORGS),--eval "(org-babel-tangle-file \"$(f)\")") \
  	  $(EVAL_PRESERVE_INDENT) \
  	  --eval "(org-babel-tangle-file \"$(ORG)\" nil \"makefile\")"

  # ---- check-cookies : 全 .el の 1 行目にある lexical-binding クッキーを検証 -------
  # `make tangle' の後に実行し、生成物すべてにクッキーがあることを確認する。
  # すべて合格なら 0 を返す。欠落があれば該当ファイルを列挙して 1 を返す。
  check-cookies:
	@echo "[check-cookies] scanning $(LISPDIR) ..."
	@fail=0; \
  	 for f in $$(find "$(LISPDIR)" -name '*.el' | sort); do \
  	   line1=$$(head -1 "$$f"); \
  	   if ! echo "$$line1" | grep -q 'lexical-binding: t'; then \
  	     echo "  MISSING: $$f"; \
  	     echo "    line1: $$line1"; \
  	     fail=1; \
  	   fi; \
  	 done; \
  	 if [ $$fail -eq 0 ]; then \
  	   echo "[check-cookies] all files OK"; \
  	 else \
  	   echo "[check-cookies] FAILED — run: make reload"; \
  	   exit 1; \
  	 fi

  # ---- reload : .elc を削除してから再 tangle し、孤立した生成物も消す ---------------------------------------
  # README.org を新しい Claude の出力に差し替えた後に使う。古いバイトコンパイル済み
  # モジュールが、新しく tangle した .el を覆い隠さないことを保証するためである。
  # このターゲットは、ソースには存在しない警告をディスク上の古いモジュールが出すという
  # 古いモジュールが出す）に対する運用上の対処である。
  #
  # tangle は、書き出すファイルを上書きするだけで、tangle 先でなくなったファイルは消さない。
  # 設定の新旧を行き来したり、モジュールを統合・改名したりすると、古い生成物が残る。そこで
  # 最後の段の clean-orphans が、どの Org 文書も tangle しない生成物を削除する。
  #
  # reload の途中で Makefile 自身が書き換わる（tangle が Makefile を生成する）ことがある。
  # make は起動時に読んだ古い定義のまま動き続けるため、書き換わったと分かったら、新しい
  # Makefile でもう一度 reload を走らせる。無限に繰り返さないよう、2 回目は RELOAD_REEXEC を立てる。
  MAKEFILE_SUM := $(shell cksum < "$(firstword $(MAKEFILE_LIST))" 2>/dev/null)
  reload: clean tangle check-cookies clean-orphans
	@echo "[reload] on-disk modules now reflect $(ALL_ORGS); restart Emacs to load."
	@if [ "$$(cksum < "$(firstword $(MAKEFILE_LIST))")" != "$(MAKEFILE_SUM)" ] && [ -z "$$RELOAD_REEXEC" ]; then \
  	  echo "[reload] Makefile が更新されたため、新しい Makefile でもう一度 reload を実行します"; \
  	  RELOAD_REEXEC=1 $(MAKE) reload; \
  	fi

  # ---- check-orphans / clean-orphans : tangle 先から外れた生成物 -------------------------
  # lisp/ personal/ scripts/ の .el .elc .py .sh のうち、どの Org 文書も tangle しないものを
  # 一覧する（check-orphans。あれば失敗）／削除する（clean-orphans）。本体は scripts/orphans.el
  # （org/tools.org の Appendix: orphans.el を参照）。scripts/orphans.el が無い古い木では何もしない。
  .PHONY: check-orphans clean-orphans
  check-orphans:
	@if [ -f "$(ROOT)/scripts/orphans.el" ]; then \
  	  ORPHANS_ROOT="$(ROOT)" ORPHANS_ORGS="$(ALL_ORGS)" $(EMACS_Q) -l "$(ROOT)/scripts/orphans.el"; \
  	else echo "[orphans] scripts/orphans.el not found; skipping"; fi
  clean-orphans:
	@if [ -f "$(ROOT)/scripts/orphans.el" ]; then \
  	  ORPHANS_DELETE=1 ORPHANS_ROOT="$(ROOT)" ORPHANS_ORGS="$(ALL_ORGS)" $(EMACS_Q) -l "$(ROOT)/scripts/orphans.el"; \
  	else echo "[orphans] scripts/orphans.el not found; skipping"; fi

  # ---- checkdoc : すべての公開 defun の docstring を検証 ---------------------------
  # LISPDIR 配下の全 .el を走査し、docstring の欠落や不正を検出する。
  # 全ファイルが合格すれば 0、警告が出れば 1 を返す。
  checkdoc:
	@echo "[checkdoc] scanning $(LISPDIR) ..."; \
  	 fail=0; \
  	 for f in $$(find "$(LISPDIR)" -name '*.el' | sort); do \
  	   result=$$($(EMACS_Q) --eval \
  	     "(progn (find-file \"$$f\") (checkdoc-current-buffer t) (kill-buffer))" \
  	     2>&1); \
  	   if echo "$$result" | grep -q 'Warning\|Error'; then \
  	     echo "  FAIL: $$f"; echo "$$result" | grep 'Warning\|Error' | head -5; \
  	     fail=1; \
  	   fi; \
  	 done; \
  	 [ $$fail -eq 0 ] && echo "[checkdoc] all files OK" || exit 1

  # ---- checkdoc-strict : 失敗時に終了する checkdoc ---------------------------------
  # 公開 defun に docstring が無いときビルドを失敗させたい CI で使う。
  # Emacs セッションがモジュールの load-path を参照できる必要がある。

  # ---- check-tangle : tangle 先を継承できない emacs-lisp ブロックを検出 -------------
  # Org の :header-args: はサブツリーにのみ継承される。見出しレベルを 1 段間違えて
  # "**** foo Design Notes" を "*** foo Design Notes" と書くと、親（*** foo）の
  # 兄弟になってしまい、その配下の src ブロックが :tangle を受け取れない。
  # tangle は静かに成功し、当該 .el だけが生成されない — 実機で 2 回踏んだ事故である。
  #
  # 本ターゲットは README.org を Org のパーサで走査し、実効 :tangle が nil または
  # "no" の emacs-lisp ブロックを行番号付きで列挙して失敗する。
  .PHONY: check-tangle
  check-tangle:
	@echo "[check-tangle] verifying :tangle inheritance in $(ALL_ORGS) ..."
	@$(EMACS) -Q --batch \
  	  --eval "(require 'org)" \
  	  --eval "(let ((bad 0)) \
  	            (dolist (f (list $(foreach f,$(ALL_ORGS),\"$(f)\"))) \
  	              (with-current-buffer (find-file-noselect f) \
  	                (org-babel-map-src-blocks nil \
  	                  (when (and (string= lang \"emacs-lisp\") \
  	                             (not (equal (org-entry-get (point) \"CUSTOM_ID\" t) \"changelog\"))) \
  	                    (let ((tgt (cdr (assq :tangle (nth 2 (org-babel-get-src-block-info t)))))) \
  	                      (when (or (null tgt) (equal tgt \"no\")) \
  	                        (setq bad (1+ bad)) \
  	                        (message \"  ORPHAN src block at %s line %d\" f (line-number-at-pos)))))))) \
  	            (if (> bad 0) \
  	                (progn (message \"[check-tangle] FAILED: %d block(s) without a tangle target\" bad) \
  	                       (kill-emacs 1)) \
  	              (message \"[check-tangle] ok\")))"

  # ---- check-emphasis : 効かない Org 強調記法（=verbatim=/~code~/*bold*）を検出 -----
  # org-emphasis-regexp-components の既定値では、開始マーカーの直前・終了マーカーの
  # 直後が半角空白・タブ・- – — ( " ' { （直前側）／ . , : ! ? ; ' " ) } [ （直後側）・
  # 行頭・行末のいずれかでなければ強調は成立しない。orgx-core.el（leaf org :config）で
  # 「」『』（）【】、。・ を PRE/POST に追加済みだが、それ以外の全角文字（！？：；等）は
  # まだこの集合に含まれない。和文の直後に =code= を続けるとマーカーが素通しされ、
  # リテラルの "=" 文字としてそのまま表示される（シンタックスハイライトも失われる）。
  # あわせて、Org の強調構文がネストをサポートしない点も検出する。*bold* の中に
  # 完全な =verbatim= / ~code~ が入っている場合（例: "*なぜ =foo= なのか*"）、内側の
  # マーカーは独立して再マッチされず literal 文字のまま表示される。
  # tangle には影響しないため、いずれも見た目の欠陥として気づかれにくい。
  #
  # 検査本体は scripts/check_emphasis.py（Appendix を参照）。標準ライブラリのみに
  # 依存する Python スクリプトであり、Emacs のバッチモードは介さない。
  .PHONY: check-emphasis
  check-emphasis:
	@python3 scripts/check_emphasis.py $(foreach f,$(ALL_ORGS),"$(f)")

  # ---- check-fboundp-guards : (fboundp 'X) ガード + #'X 参照の整合性を検査する -------
  # (when/if (fboundp 'X) ... #'X ...) という形（X をコマンドとして登録・束縛している
  # 箇所）だけを対象に、X が実際に解決可能か（ローカル定義 / leaf の :commands /
  # 同名 leaf パッケージの eager load / ドキュメント上の autoload 明記）を機械的に
  # 検査する。dev-music.el の emms 抜け、restart-emacs の宣言忘れ、のような
  # 「エラーは出ないが黙って何も起きない」バグを次に防ぐためのツール。
  # $(LISPDIR) と $(PERSONALDIR) を対象にするため、事前に tangle 済みであること。
  # 検査本体は scripts/check_fboundp_guards.py（Appendix を参照）。
  .PHONY: check-fboundp-guards
  check-fboundp-guards:
	@python3 scripts/check_fboundp_guards.py "$(LISPDIR)" "$(PERSONALDIR)" "$(EARLY)" "$(INIT)"

  # ---- check-bytecomp : バイトコンパイル警告の集計 ------------------------------
  # init を読み込んだ Emacs で lisp/ personal/ early-init.el init.el をすべてバイト
  # コンパイルし（出力は一時ディレクトリで、lisp/ には .elc を作らない）、警告があれば
  # 一覧して終了コード 1 で終わる。パッケージが読み込まれた状態でコンパイルするため、
  # 読み込み前の警告（未宣言の変数・関数）は出ない。約 40 秒かかるので lint には含めない。
  # 本体は scripts/check-bytecomp.el（org/tools.org の Appendix: check-bytecomp.el を参照）。
  # ---- check-modules : lisp/modules.el と lisp/ 配下の整合性を検査する -----------------
  # my:modules と my:modules-extra に挙がるモジュールの実在と provide、層の並び順、
  # 上位層への明示的な require、どちらにも載らない .el を、Emacs なしで検査する。
  # 本体は scripts/check_modules.py（org/tools.org の Appendix: check_modules.py を参照）。
  .PHONY: check-modules stats
  check-modules:
	@python3 scripts/check_modules.py "$(ROOT)"

  # ---- stats : 層ごとのファイル数・行数・コメント率を表示する ----------------------
  # AGENTS.md に書く数値は手で数えるとずれるため、この出力から写す。
  stats:
	@python3 scripts/stats.py "$(ROOT)"

  # Emacs の標準エラーは、通常は雑音（Batch mode does not support ... の警告や、[modules] の行）なので捨てる。
  # ただし終了コードが 2 以上（Lisp のエラーは 255）のときは、雑音を除いて末尾を表示する。
  # 終了コード 1 は通常の結果である（check-bytecomp は警告あり、check-cheatsheet は差分あり）。
  EMACS_NOISE_RE := ^\[modules\]\|^Loading\|Batch mode does not support

  .PHONY: check-bytecomp
  check-bytecomp:
	@echo "[check-bytecomp] byte-compiling (init を読み込むため約 40 秒かかる) ..."
	@err=$$(mktemp); \
  	  ROOT="$(ROOT)" $(EMACS_BATCH) -l "$(EARLY)" -l "$(INIT)" -l "$(ROOT)/scripts/check-bytecomp.el" 2>"$$err"; rc=$$?; \
  	  if [ $$rc -gt 1 ]; then echo "[check-bytecomp] Emacs が異常終了しました (終了コード $${rc})。標準エラーの末尾:" >&2; \
  	    grep -v '$(EMACS_NOISE_RE)' "$$err" | tail -20 >&2; fi; \
  	  rm -f "$$err"; exit $$rc

  # ---- smoketest : 起動と動作のスモークテスト ------------------------------------------
  # init を読み込んだ Emacs で、キー割り当て・補完・各拡張の設定が実際に動くかを確かめる。
  # 失敗が 1 件でもあれば終了コード 1 で終わる。約 40 秒かかるので lint には含めない。
  # バッチの Emacs は straight のビルドキャッシュを書き直して GUI 起動を壊しうるため、
  # 本体が開始時に退避し、終了時に元へ戻す。
  # 本体は scripts/smoketest.el（org/tools.org の Appendix: smoketest.el を参照）。
  .PHONY: smoketest
  smoketest:
	@echo "[smoketest] init を読み込んで動作を確かめる (約 40 秒かかる) ..."
	@err=$$(mktemp); \
  	  ROOT="$(ROOT)" $(EMACS_BATCH) -l "$(EARLY)" -l "$(INIT)" -l "$(ROOT)/scripts/smoketest.el" 2>"$$err"; rc=$$?; \
  	  if [ $$rc -gt 1 ]; then echo "[smoketest] Emacs が異常終了しました (終了コード $${rc})。標準エラーの末尾:" >&2; \
  	    grep -v '$(EMACS_NOISE_RE)' "$$err" | tail -20 >&2; fi; \
  	  rm -f "$$err"; exit $$rc

  # ---- cheatsheet : キーバインド一覧の SVG を、実際のキーマップから作る ---------------
  # init を読み込んだ Emacs でキーマップを読み、svg/emacs_keybindings_cheatsheet.svg を
  # 書き直す。check-cheatsheet は書き出さずに、コミット済みの SVG と同じかを調べる
  # （違えば終了コード 1）。約 40 秒かかるので lint には含めない。
  # 本体は scripts/cheatsheet.el（org/tools.org の Appendix: cheatsheet.el を参照）。
  .PHONY: cheatsheet check-cheatsheet
  cheatsheet:
	@err=$$(mktemp); \
  	  ROOT="$(ROOT)" $(EMACS_BATCH) -l "$(EARLY)" -l "$(INIT)" -l "$(ROOT)/scripts/cheatsheet.el" 2>"$$err"; rc=$$?; \
  	  if [ $$rc -gt 1 ]; then echo "[cheatsheet] Emacs が異常終了しました (終了コード $${rc})。標準エラーの末尾:" >&2; \
  	    grep -v '$(EMACS_NOISE_RE)' "$$err" | tail -20 >&2; fi; \
  	  rm -f "$$err"; exit $$rc
  check-cheatsheet:
	@err=$$(mktemp); \
  	  ROOT="$(ROOT)" CHEATSHEET_CHECK=1 $(EMACS_BATCH) -l "$(EARLY)" -l "$(INIT)" -l "$(ROOT)/scripts/cheatsheet.el" 2>"$$err"; rc=$$?; \
  	  if [ $$rc -gt 1 ]; then echo "[check-cheatsheet] Emacs が異常終了しました (終了コード $${rc})。標準エラーの末尾:" >&2; \
  	    grep -v '$(EMACS_NOISE_RE)' "$$err" | tail -20 >&2; fi; \
  	  rm -f "$$err"; exit $$rc

  # ---- verify : コミット前の確認をまとめて実行する -------------------------------------
  # lint（静的チェック）、check-bytecomp（バイトコンパイル警告）、check-cheatsheet（キーバインド一覧 SVG が
  # 実際のキーマップと同じか）。後の 2 つは約 40 秒ずつかかるため lint には入れず、ここでまとめる。
  # キーを入れる関数を足したのに一覧 SVG を作り直していない、といった食い違いを、コミット前に見つける。
  .PHONY: verify
  verify: lint check-bytecomp check-cheatsheet
	@echo "[verify] all checks passed"

  # ---- lint : check-tangle + check-emphasis + check-cookies + check-fboundp-guards + check-modules + check-orphans +
  # checkdoc をまとめて実行 -----------------------------------------------------------
  # コミット前に静的品質チェックをすべて走らせるための単一ターゲット。
  .PHONY: checkdoc lint
  lint: check-tangle check-emphasis check-cookies check-fboundp-guards check-modules check-orphans checkdoc
	@echo "[lint] all checks passed"

  # ---- package-lint : 任意 — load-path 上に package-lint が必要 --------------------
  # MELPA 形式のパッケージヘッダと依存宣言を検証する。
  # 個人設定のワークフローでは不要だが、モジュールを独立パッケージとして切り出す際に
  # 有用である。
  # インストール: M-x package-install RET package-lint RET
  .PHONY: package-lint
  package-lint:
	@echo "[package-lint] scanning $(LISPDIR) ..."; \
  	 $(EMACS_Q) $(EVAL_LEAF) \
  	   --eval "(require 'package-lint nil t)" \
  	   --eval "(if (featurep 'package-lint) \
  	               (let ((files (directory-files-recursively \"$(LISPDIR)\" \"\\\\.el$$\"))) \
  	                 (dolist (f files) (package-lint-batch-and-exit))) \
  	               (message \"[package-lint] not installed; skipping\"))""
#+end_src
